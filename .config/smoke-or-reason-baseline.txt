# `[tool.*]` entries with no `smoke` probe — each with the reason it has none.
#
# A RATCHET, not an allowlist: this file may only SHRINK. `check-smoke-or-reason`
# fails when a tool here gains a probe (delete its line), when a line names a
# tool the index no longer has (delete it), and when a NEW tool arrives with
# neither a probe nor a line here.
#
# WHY IT EXISTS — phase-447 C1 / RFC-0099 D5. `nros setup` now runs each tool's
# `smoke` probes on the INSTALL path, so a dist that downloads, verifies and
# unpacks and then cannot RUN fails at unpack, naming the probe and what it
# printed. That covers exactly the tools that declare a probe, and
# `failing_smoke`'s own contract is that absent `smoke` means NO OPINION, not a
# pass. Without this file the install-path check would be a loud failure over 12
# tools and a silent success over the other 13.
#
# A reason says what WOULD be probed and why nobody does. Two kinds appear
# below, and the difference matters: `corrosion` and the `zephyr-sdk` pair have
# STRUCTURAL reasons that will not change, everything else is DEBT and reads
# like it.
#
# Format: `<tool>: <reason>`, one per line; `#` comments.

# --- structural: there is nothing a prefix-relative argv can run --------------

corrosion: installs CMake package files and no executable — measured, the 0.6.1-nros1 prefix holds only lib/cmake/Corrosion and share/cmake. Its usability is answered at CONFIGURE time by the `nano-ros: Corrosion <ver> via <origin>` line (issue 0500), which is where a wrong version actually bites.
zephyr-sdk: a probe's `run` is prefix-relative argv and this dist unpacks to `<prefix>/zephyr-sdk-<version>/`, not `<prefix>/bin` — so any probe would restate the version already on the line above it, and drift from it on the next bump. The SDK's own `setup.sh -t <target>` is what makes it usable, and that has no expression in this schema.
zephyr-sdk-1-0-1: same layout as [tool.zephyr-sdk] above, and the same version-in-the-argv objection. These are the `_minimal` archives, so the toolchains are not even present until `setup.sh -t` fetches them — a probe of the unpacked prefix would measure the part nobody builds with.

# --- debt: a probe is possible and nobody has measured one -------------------

arm-fvp: `bin/FVP_BaseR_AEMv8R` exists after the `--strip-components=1` unpack, and no probe has been run against it. x86_64 Linux only, and no host here has provisioned it, so its banner and its exit behaviour are both unmeasured — writing an `expect` from the documentation is how a probe passes on nothing.
cyclonedds: `bin/idlc` is the candidate. Unmeasured: the dist bundles its own `libddsc`, so what a bare probe resolves depends on RUNPATH and on whether a ROS cyclonedds is on the loader path — exactly issue 0774's confound, which is worth measuring before asserting on.
esp32-qemu: source-built only, so the binary is produced by the host that will run it. A probe is still worth having (a build can succeed and produce something that will not start) and none has been measured.
genromfs: source-built only. Unmeasured — its `-h` output is the only surface and nothing has been run to see what it prints or on which stream.
make: source-built only from an upstream tarball; `bin/make --version` prints a GNU banner. Unmeasured here, and the prefix ships both `make` and `gmake`, so which name a probe should assert on is part of the question.
ninja: has dists for three hosts. `bin/ninja --version` prints `1.13.2` and nothing else — measured 2026-09-11 on the provisioned prefix — so an `expect` has to assert the pinned version and then move with every bump, or assert a substring so short it proves nothing. Deciding what that probe should assert is the open part, not whether one can run.
play_launch_parser: source-built only (`cargo install` from our own play_launch pin), and its `[tool.*] system` list already names libpython/libexpat/libz — so it links an interpreter and is exactly the shape whose probe would be worth having. Unmeasured.
xrce-agent: closest to ready, and deliberately not taken here. `bin/MicroXRCEAgent` is a WRAPPER that sets LD_LIBRARY_PATH and execs `../lib/MicroXRCEAgent.real`; the smoke path strips LD_LIBRARY_PATH before spawning, and the wrapper's own export survives that — measured 2026-09-11 on the linux-x86_64 PREBUILT (provenance kind = "prebuilt"), which printed its usage banner with LD_LIBRARY_PATH/PYTHONPATH/PYTHONHOME all removed. One host of three, and the source-built shape is unmeasured, so the `expect` string is not yet evidenced for the dists a probe would also bind.
