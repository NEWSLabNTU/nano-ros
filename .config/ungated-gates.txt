# Gates that live in a lane NO pull_request or merge_group job runs.
#
# A RATCHET, not an allowlist: this file may only shrink.
# `check-gate-visibility` fails when a gate here becomes reachable from a
# gating lane (delete its line) and when one appears that is not here (either
# move it, or add a line and say why) — so the invisible set cannot silently
# grow and cannot silently go stale.
#
# EMPTY, as of issue 0993. It held 19, then 20; every one of them now runs on a
# pull request:
#
#   * 20 gates that need nothing BUILT moved to the fast line.
#   * The remaining build tier gained its prerequisites on the PR path — the
#     `generate-bindings` and compile-check-fixture steps that already lived in
#     the same job, merely guarded `schedule`/`workflow_dispatch` — plus a
#     parallel runner, which took it from ~587 s serial to 190 s wall at -P32.
#
# It stays here, empty, on purpose. The next gate that lands somewhere no pull
# request runs has to add a line, and that line is the question "does it need to
# be there?" asked at the only moment anyone will ask it.
#
# Membership, if it is ever non-empty again, is TESTED and not argued — and the
# test has two halves, because the first one is not sufficient:
#
#   1. a pristine worktree (`git worktree add --detach`) proves the gate needs
#      nothing BUILT;
#   2. CI's own container proves it needs nothing INSTALLED. `sched-dim-arms`
#      passed (1) on a provisioned host and still failed (2) on `FreeRTOS.h`.
#
