# What `check-cpp-capability-layout` must tolerate today: NOTHING.
#
# READ THE LAST SECTION FIRST. This file was a RATCHET -- it could only SHRINK,
# a line that no longer matched what the gate measures was a FAILURE, and a
# violation not listed here was a failure too. phase-456 W6 turned it into a
# CONSTANT: a row of any kind is now a hard failure, and the text between here
# and there is the record of what the ratchet measured and why, kept in the
# past tense it earned rather than deleted.
#
# The three kinds below survive only as the vocabulary of the refusal message
# and of that record. They mean different things and the gate accepts none:
#
#   diverges <subject>     `sizeof(subject)` follows a capability macro. This is
#                          the defect the gate exists to catch. Delete the line
#                          in the commit that fixes the member.
#   hosted-only <subject>  the subject does not EXIST in the freestanding arm.
#                          Absence is not a layout divergence -- no freestanding
#                          TU can name the type, so no object of it crosses the
#                          boundary and no two TUs can disagree about its shape.
#                          It is DECLARED rather than inferred because "the type
#                          was supposed to exist there" is a real defect wearing
#                          the same clothes; issue 1204 is the version of this
#                          gate that inferred it and passed on absence.
#   std-only <subject>     the subject does not EXIST hosted with
#                          `-DNROS_CPP_STD` withheld (phase-438 W4's arm). Same
#                          argument as `hosted-only`, on a different axis, and
#                          a SEPARATE kind on purpose: one line must not excuse
#                          two arms, or a type that starts vanishing on the
#                          second one is absorbed by an exemption written for
#                          the first.
#
# Subject spellings are the DERIVED ones -- `scripts/check/
# cpp_capability_subjects.py` prints the list. A line naming a subject the
# derivation no longer produces is a failure, so a renamed type cannot leave a
# dead exemption behind.
#
# --- the `diverges` entries: NONE, and that is issue 1225 closed -------------
#
# There were five, spelling three types and ONE member: `nros::Timer` and
# `nros::GuardCondition` each held an `#ifdef NROS_CPP_STD`
# `std::unique_ptr<std::function<void()>> closure_`, the timer-array holder
# `nros::NodeWithTimers<N>` followed it at 8 x the pool depth, and
# `rclcpp::Timer` / `rclcpp::TimerBase` are aliases of `nros::Timer`, which is
# the spelling a ported file writes.
#
#     nros::Timer               24 -> 32   with -DNROS_CPP_STD=1
#     nros::GuardCondition      32 -> 40
#     nros::NodeWithTimers<4>  328 -> 360
#
# phase-442 W1 took the decision issue 1225 had already made -- STATE HIDES
# BEHIND A POINTER ONLY WHEN IT EXCEEDS A POINTER. These differ by exactly 8
# bytes, which IS a pointer, so the member is UNCONDITIONAL and spelled
# `void*`: the same 8 bytes the freestanding arm would have paid for an
# indirection, one stable layout, and no dereference on the hot path. The
# pointee is a block whose head is `detail::HostedBlockBase`, carrying its own
# destroyer so that `~Timer()` -- compiled in both configurations -- frees it
# without naming a hosted type. `rclcpp::Node::hosted_` already had that shape;
# `nros/hosted_block.hpp` is now the one place it is written.
#
# Measured after the fix, all three arms: Timer 32, GuardCondition 40,
# NodeWithTimers<4> 360.

# --- the `hosted-only` and `std-only` entries: NONE --------------------------
#
# There were six, three types under two kinds. `rclcpp::Rate` (and `WallRate`,
# its alias) sat inside `#ifdef NROS_CPP_HAS_STD_CHRONO`; `rclcpp::NodeOptions`
# sat inside `#if defined(NROS_CPP_HAS_STD_STRING) &&
# defined(NROS_CPP_HAS_STD_VECTOR)`. Absence is not a layout divergence -- no
# freestanding TU could name the type, so no two TUs could disagree about its
# shape -- but it is a whole type appearing and disappearing with a toolchain,
# which RFC-0096 D1 is the decision against.
#
# phase-442 W5 removed both gates, and the measurement is why they were
# affordable: `Rate`'s gate was paying for two members out of five, and
# `NodeOptions`' for ONE out of 23. `Rate::period()` returns `nros::Duration`
# instead of `std::chrono::nanoseconds`; `NodeOptions::arguments()` takes a
# DEDUCED parameter instead of `const std::vector<std::string>&`, which is
# strictly better for a porting user too -- the same call site binds, and a
# caller passing something else still gets the migration message rather than
# "no matching function". Both refusals are unchanged.
#
# Measured after: NodeOptions 1, Rate 16, WallRate 16, identical on all three
# arms.
#
# One residue, recorded rather than hidden: `Rate`'s `std::chrono` CONSTRUCTOR
# is still behind `NROS_CPP_HAS_STD_CHRONO`. That is a gate on a METHOD, which
# this rule permits -- `sizeof(Rate)` is `int64_t` + `uint64_t` everywhere -- but
# W8's acceptance is zero `NROS_CPP_HAS_*` in the tree, so it is W8's to resolve.

# No rows remain in any of the three kinds. W1's `diverges` rows came off in
# the commit that fixed the member (see the section above), and W5's
# `hosted-only` / `std-only` rows came off with the gates they recorded.
#
# THIS FILE IS NO LONGER A RATCHET -- phase-456 W6, 2026-09-21.
#
# A row of ANY kind is now a hard failure. The three kinds survive only as the
# vocabulary of the refusal message and of this record; the gate accepts none
# of them. Why: a ratchet is the right instrument for debt you intend to pay,
# and the debt is paid. What an empty slot holds after that is not tolerance
# for something measured but a place to put the NEXT violation -- and the rule
# it would excuse has no legitimate exception, because two TUs of one image may
# legitimately disagree about a capability macro (px4 sets -DNROS_CPP_STD on a
# single module of a larger image) and would then link, write an object through
# one layout and read it through the other. Issue 0135 is that bug, shipped.
#
# WHAT IS STILL PERMITTED, so the constant is not read as more than it says: a
# capability macro may gate a METHOD, and several do -- `Rate`'s `std::chrono`
# constructor, the whole `NROS_CPP_NODE_HOSTED` block on `rclcpp::Node`. Adding
# a method changes no layout; the gate's selftest case 2 proves it lets that
# through. What is refused is a capability macro reaching a MEMBER, a base
# class, or the EXISTENCE of a public type.
#
# The paragraph above about `Rate`'s constructor said "W8's acceptance is zero
# `NROS_CPP_HAS_*` in the tree, so it is W8's to resolve". That is still true
# and still not resolved; it is not this file's business either way, because a
# gated method has never needed a row here.
#
# The file stays rather than being deleted: the gate requires it to EXIST (an
# absent file and an empty one are different states, and only one of them is
# checked), and this is the record of what the ratchet measured and why.
