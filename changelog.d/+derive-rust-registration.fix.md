A Rust node package in an image that also runs C or C++ nodes no longer needs a `CMakeLists.txt` or `<build_type>nros_cmake</build_type>`. The build registers it from its bringup's `[[component]]` row (package, class and instance), on the native CMake road and on the generated Zephyr application alike, so the same Rust package builds unchanged in a Rust-only image and in a mixed one. A package that ships its own `CMakeLists.txt` keeps it. `nros new … --to <bringup>` stops writing the CMake shim, and the "Mix languages" book page drops the step.
