On Zephyr, a thread that dies while it is delivering a log record no longer silences logging for the rest of the run. Before, every later record from every thread waited for the dead thread and was lost without a word. Now a fatal error handler that calls `nros_zephyr_log_dead_holder_check(k_current_get())` prints one line naming the thread and frees the log path, so later records reach the console again. `CONFIG_NROS_FAULT_LOG`'s handler already calls it. An application with its own `k_sys_fatal_error_handler` that returns should call it too. It needs `CONFIG_THREAD_STACK_INFO`.
