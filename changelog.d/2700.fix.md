`features` and `node_interfaces` stated in `[image.<id>]` (or `[image_defaults]`) now reach a generated workspace entry, a single-package leaf and a cmake image the same way on both halves: the cargo features or capability list the image builds with, the services `nros::main!` and `codegen entry` register, and the sizing descriptor's `infra_families` with the pools derived from it. Before, a generated workspace entry built and sized from `[system]` alone, so an image-level opt-in was ignored and an image-level `node_interfaces = "none"` still built and sized the stock services. `nros codegen entry`, `nros config show --format cmake`, `nros dev image sizing-descriptor` and `nros dev image entity-inventory` take `--image <id>`, which the cmake modules pass from `NROS_IMAGE`; a C/C++ workspace image, configured in a cmake configure shared by its coordinate, still reads `[system]`.
