`rclcpp::PollingActionClient<A>::try_recv_result` / `try_recv_result_sized`
decode the result from byte 8 of the get_result reply, after the status byte's
alignment pad; they skipped 5 bytes and every typed result failed to decode.
`try_recv_feedback` likewise decodes the fields after the goal id instead of
from byte 0. The action frame offsets now have one spelling,
`nros_node::action_frame`, read by every C, C++ and Rust consumer; C/C++ code
that decodes raw polled frames gets them as `NROS_CPP_ACTION_*_PAYLOAD_OFFSET`
and `RCLC_ACTION_*_PAYLOAD_OFFSET`. The C poll path now hands feedback to the
callback with its encapsulation header, as the executor dispatch always did.
