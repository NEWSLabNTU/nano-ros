Rust images (`nros::main!`) now apply the same sched-task spin-period rule as C and C++ images. An unset `spin_period` is derived from the task's fastest member release (its tightest timer) instead of defaulting to 1 ms. An authored `spin_period` longer than that release is refused at build time, as it already was for C and C++: before, the member's timer silently ran at the spin rate. The refusal names the sched task, both periods, the member, and the `[tasks.<name>] spin_period` setting to change. No in-tree Rust image is refused. `realtime-rust`'s derived bringup now spins its `ctrl` task every 10 ms and its `telem` task every 100 ms instead of every 1 ms.
