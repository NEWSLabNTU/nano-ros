A Zephyr C or C++ image no longer relinks on every `nros build` and `nros run`
when nothing changed. nros-c and nros-cpp's cargo builds now use separate
target directories, so they stop rebuilding each other's crates. A repeated
`nros build` of an already-configured image runs `cmake --build` instead of
making `west build` configure again, which in Zephyr always regenerates the
syscall headers. A changed board, overlay, module or environment still
reconfigures (issue 2281).
