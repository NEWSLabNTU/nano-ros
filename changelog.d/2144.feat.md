An executor can tell a host loop that work arrived, so the host spins instead of polling (RFC-0112 D2.2 "Readiness out", issue 2144). `Executor::set_ready_notifier(fn, ctx)` installs one notifier, called for every sample, request or reply on the executor's sessions — through the session wake or an entity waker, attributed or not, whichever worker it wakes — and for a guard condition triggered from another thread. On Linux, `Executor::ready_fd()` (feature `signal-fd-wake`) returns a non-blocking eventfd that becomes readable at the same moments, for GLib, Qt, epoll or tokio `AsyncFd`. Both cross the FFI as `rclc_executor_set_ready_notifier` and `nros_cpp_executor_set_ready_notifier` / `rclcpp::Executor::set_ready_notifier`. A poll-only backend (XRCE), which learns of an arrival only inside a spin, refuses with `Unsupported` instead of installing a notifier that never fires; `Executor::ready_notifier_supported()` asks first.
