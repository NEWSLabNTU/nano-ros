A `linux` image (Rust, C or C++) now uses the `domain_id` and `locator` its `system.toml` states when `$ROS_DOMAIN_ID` / `$NROS_LOCATOR` do not set them. Before, the `linux` board dropped them and joined domain 0, dialling the backend's default. The environment still wins, and the image now warns at boot when it overrides a stated value, naming both (`ROS_DOMAIN_ID=5 overrides system.toml's domain_id=42`). The host runners `nros_board_native_run_{components_named,sched_tasks,levels}_in` take the same leading `(locator, domain_id)` pair as the RTOS runners: a generated entry from before this change must be regenerated (`nros build` does it).
