A zenoh Zephyr image reserves one task stack fewer: `CONFIG_NROS_ZEPHYR_TASK_SLOTS` now defaults to 2 with `NROS_ZENOH_TX_BATCH` and 1 without (was 3 and 2), because zenoh-pico 1.10 runs the read path, lease, keep-alive and reconnect on one executor thread (RFC-0110 D2). At the default `NROS_ZEPHYR_TASK_STACK_SIZE` that is one stack less per image. An application that calls `Executor::open_threaded` still states the knob to cover its own threads.
