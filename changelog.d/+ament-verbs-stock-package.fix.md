The ament verbs now take a stock ROS 2 C++ package's CMakeLists as written (phase-488, found porting Autoware's `autoware_external_cmd_selector`). `rclcpp_components_register_node(... EXECUTABLE ...)` configures; it failed on every call with "Unknown argument to GENERATE subcommand". Its generated `main` now declares the component class and calls a factory that `RCLCPP_COMPONENTS_REGISTER_NODE(<class>)` defines in the component's own source, so it no longer needs the class's header. `ament_auto_add_library(... SHARED ...)` builds a static library, because a shared one linked a second copy of the runtime and the image died at start-up. `ament_auto_find_build_dependencies()` reads `package.xml`: `ament_auto_add_*` give the target the package's `include/` and every dependency nano-ros provides, and list the ones it does not. A message package installed under `AMENT_PREFIX_PATH` resolves through nano-ros codegen instead of the installed ROS package. `diagnostic_updater` carries `diagnostic_msgs`. An ament package built on a host that declares no `NROS_FEATURES` gets `param_services` in its runtime, as upstream rclcpp always has, and its ament targets are compiled to start them (the node constructor that does is in the C++ surface); setting `NROS_FEATURES` still decides.
