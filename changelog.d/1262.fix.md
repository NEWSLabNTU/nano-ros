`nros setup` now records every tool it was asked for in `nros-sdk.lock`, and puts that lock in the project rather than in whatever directory you ran from. A tool already in the shared store planned as `present (skip)` and was written nowhere, so the second project to ask for an SDK committed a lock naming one toolchain while needing two — and left `nros store gc` believing nothing pinned the other. The lock path was a relative `nros-sdk.lock`, so it followed the cwd; it is now anchored to the nearest ancestor carrying a pin file (`nros-sdk.lock`, `nros-sdk-index.toml`, `nros-toolchain.toml`), which is the same walk `nros store gc` reads them back with. `nros setup --tool` prints which file it wrote.
