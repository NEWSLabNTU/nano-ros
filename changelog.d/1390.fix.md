The `nros-c` / `nros-cpp` size probe no longer reserves the executor's `.bss`
backing in the nested build it spawns to measure a layout. The probe inherits
`NROS_BOARD_TOML` — it has to, because that file's contents carry knobs that do
change a probed size — and so it was picking a board's `[board.knobs.executor]
backing_u64s` claim off the RFC-0049 ladder while the image's own sizing knobs,
which travel through a different route, never reached it. `nros-node`'s
`stated >= default` compile-time assertion therefore ruled inside the probe on a
pairing that exists in no image. The probe now pins the knob to its documented
opt-out, which changes nothing it measures: the generated `NROS_EXECUTOR_SIZE`
and `*_OPAQUE_U64S` values are byte-identical before and after.
