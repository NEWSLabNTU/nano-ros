The FreeRTOS heap and the ThreadX byte pool now grow with the image's nodes. Every node past the first that serves the parameter services adds room for its six servers' buffers, and every further lifecycle state machine adds room for its five. Both defaults had been measured on one-node images, so a ThreadX image with five parameter-serving nodes ran its byte pool dry at boot. An image with one node gets exactly the heap it got before. An explicit heap size still wins, and a ThreadX image whose stated pool is too small for its nodes is refused at build time.
