A component that declares a `double` parameter whose default is infinity or NaN (an "unbounded" timeout written as `std::numeric_limits<double>::infinity()`, say) no longer breaks `nros configure`. The metadata sidecar wrote the default as a bare `inf`, which is not JSON, so planning failed with "invalid source metadata JSON ... expected value". A non-finite default is now recorded as the string `"inf"`, `"-inf"` or `"NaN"`; the parameter's `type` still says `double`.
