A package's `nros-knobs.toml` must follow the configuration naming rule, and a package that breaks it fails to load in your own build, with a message naming the row and the rule it breaks. A key is `<owner>.<name>`, two lower-case segments under the package's owner word; every other spelling derives from it (`NROS_<OWNER>_<NAME>`, `CONFIG_NROS_<OWNER>_<NAME>`); a memory size ends `_bytes` and a duration `_ms` or `_us` (`_size`, `_kb`, `_buffer` and `_u64s` are refused, while `_mtu`, `_baud` and `_frames` are accepted as they stand); no build-time name is also a run-time variable; every name nano-ros defines starts `NROS_`; a retired name is never reused; and no setting takes the variable of an SDK resource location such as `FREERTOS_DIR`. The built-in settings that break the rule today are renamed in later releases.
