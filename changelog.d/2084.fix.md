`CONFIG_NROS_ZEPHYR_STACKS_IN_DTCM` now moves the tier/level stacks too: the shim's tier pool (`nros_tier_stacks`) and a generated C/C++ entry's declared level stacks follow it through a new knob, `CONFIG_NROS_ZEPHYR_TIER_STACKS_IN_DTCM` (default: the task-stack knob; turn it off to keep level stacks in SRAM). Before, only the task stacks moved, and on the MR-CANHUBK344 a Rust level image with a 64 KiB level slot overflowed RAM by 30,028 B. Either knob on a devicetree with no "DTCM" memory region is now a compile error instead of an orphan section (issue 2084).
