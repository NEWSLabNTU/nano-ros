`nros build` now refuses a nano-ros knob passed as a CMake `-D`, in any spelling (`-DNROS_FREERTOS_APP_STACK_KB=64`, its `CONFIG_NROS_*` or legacy name), through `--cmake-args=`, an `@file`, or `[image.<id>.build] cmake_args`. The refusal applies to every knob that `system.toml` delivers to the build on every road (cargo, CMake and west). A knob is meant to live in one committed place, so that a value given on one road's command line is not the one another road silently builds with. Move the value to the image's `[image.<id>.knobs.<group>]` table. The error names the exact group and key, for example `[image.<id>.knobs.freertos] app_stack_kb = 64`. Knobs that nano-ros cannot yet show reach every road are still accepted as `-D`. On the Zephyr (west) road, `--cmake-args=-DNROS_OVERRIDE_<ID>=<value>` remains the one-build override.
