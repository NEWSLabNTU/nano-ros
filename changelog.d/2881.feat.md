`RCLCPP_LOG_MIN_SEVERITY` is new, with upstream's six values (`RCLCPP_LOG_MIN_SEVERITY_DEBUG` .. `_NONE`): define it and every `RCLCPP_*` log macro below that level, in every family (plain, `_ONCE`, `_SKIPFIRST`, `_THROTTLE`, `_SKIPFIRST_THROTTLE`, `_STREAM`), compiles to an empty statement whose arguments are never evaluated. The run-time level and the `log.max_level` ceiling filter a record only after its arguments are computed, so a per-cycle debug line in a control loop still cost the work; the floor removes it. The C API gains the twin `RCLC_LOG_MIN_SEVERITY` (`RCLC_LOG_MIN_SEVERITY_TRACE` .. `_NONE`, numbered as `log.max_level`), which gates `RCLC_LOG_*` and `RCLC_LOG_*_THROTTLE` and also applies to `RCLCPP_*`. Unset, nothing changes.
