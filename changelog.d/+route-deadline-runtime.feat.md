A new runtime contract rule, `route-deadline-runtime` (rule code 11), supervises an input-triggered route with a deadline: a take of the trigger still unanswered at `take + route_deadline_ms` is reported, and the executor's reaction hook is called with the row's reaction id, row index and mechanism, instead of waiting for an output that may never come. The executor ends its park at the earliest such deadline (`WakeSourceId::RouteDeadline`). C and C++ register the hook with `nros_cpp_executor_set_reaction_hook` (or define `nros_app_reaction_hook`, which a generated entry with a supervised row installs), and a port supervising with its own timer reads the due time from `nros_cpp_executor_route_next_due_us`. Monitor rows gain `route_deadline_ms`, `reaction_id` and `mechanism`, all zero by default, so existing rows and images are unchanged. With no `set_fault_handler`, a sched context's `fault` deadline action now calls the reaction hook when one is installed instead of panicking.
