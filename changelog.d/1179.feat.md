Typed subscriptions are sized from their message type on every backend, not
only on Cyclone. Generated messages now state their size bound on
`RosMessage` (`MAX_SERIALIZED_BOUND`), so on zenoh and XRCE a subscription
that names no buffer size gets one fitted to its type instead of the
image-wide default. `.message_info()` and `.safety()` subscriptions are sized
the same way; on a native zenoh `Int32` safety listener, the arena it claims
fell from 1,736 to 744 bytes. A hand-written message type keeps the old
default unless it overrides the new constant. The codegen version moves to
15; trees generated at 14 still build.
