A build lane that discards the metadata probe's build tree (`NROS_METADATA_PROBE_CACHE=0`) now keeps the probe's outputs. It used to delete the whole tree, including the message bound tables that a C or C++ Zephyr image's configure reads, so that configure refused with "the metadata probe generated no bound table", and every C/C++ component was probed again on the next configure. The discard now keeps the probe aggregate, the bound tables and the two files the freshness check reads (112 KB on `examples/workspaces/levels-cpp`, where the full tree is 79 MB).
