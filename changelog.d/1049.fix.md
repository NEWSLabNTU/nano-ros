Five C-API contracts behind adopted rcl names now behave the way upstream's do (phase-417 stage 3). `rcl_client_is_valid` / `rcl_service_is_valid` / `rcl_subscription_is_valid` and their name accessors accept every state the entity actually works in — a REGISTERED or POLLING client, a polling service or subscription — instead of `INITIALIZED` alone, so the upstream guard no longer rejects a live entity and `rcl_client_get_service_name` no longer hands NULL to a `printf("%s")`. `rcl_node_is_valid` consults the node's CONTEXT, so it reports false over a session `rclc_support_fini` has dropped rather than passing the guard into a use-after-free. `rcl_timer_fini` is idempotent, as `rcl/timer.h` promises for a NULL or already-invalid timer. `nros_log_severity_t` sits on rcutils's number line (`UNSET=0, DEBUG=10 … FATAL=50`) and is a transparent `int`-width mirror of the C enum, so a ported rcutils constant means what it says instead of arriving as an invalid discriminant. **BREAKING for C callers:** `nros_timer_get_time_until_next_call` now takes rcl's shape, `nros_ret_t (const nros_timer_t *, int64_t *)` — it drops the caller-supplied clock, reads the executor arena rather than a field no dispatch path updates (it answered `0` for every running timer), and reports overdue as a negative value.
