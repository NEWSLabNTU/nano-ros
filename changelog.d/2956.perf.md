On zenoh, the runtime's own `~/transition_event`, `/rosout` and `/parameter_events` writers no longer hold a zenoh publisher. Each sample is a bare put on a key built for the call. A declared zenoh-pico publisher keeps about 1.4–1.8 KB of heap and a publisher slot, so each managed node saves one, and an image saves one for `/rosout` and one for `/parameter_events`. The graph still lists every writer as a publisher, with its own gid and sequence number in each sample. XRCE and Cyclone DDS keep a held writer for each, as before. A C backend opts in through the new `publish_on_demand` vtable slot; one that leaves it NULL is unaffected.
