A refused resolve leaves no SystemModel any consumer can trust. When `nros sync` is refused (a contract the resolver rejects), the previous `system_model.yaml` is moved aside to `system_model.refused-<utc-stamp>.yaml` and a `system_model.refused` marker names the check and the input that changed; `nros model-path`, `ws entity-inventory`, `codegen-system` and `codegen entry` all refuse the model, naming the marker, until the next successful sync. Every consumer now verifies the model's provenance (resolver pin, recorded input hashes, and a launch-tree input the model never recorded) through one gate, not only sync.
