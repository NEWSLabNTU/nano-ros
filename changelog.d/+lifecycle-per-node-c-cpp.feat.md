An image can now hold several managed C or C++ nodes, each with its own lifecycle. In C, `rclc_node_register_lifecycle_services(node)` gives a bound node its own services and state machine, and `rclc_node_lifecycle_get_current_state`, `rclc_node_lifecycle_change_state` and `rclc_node_lifecycle_register_on_*` act on that node's machine. The executor-level `rclc_executor_lifecycle_*` calls still serve an image with one managed node. In C++, an `rclcpp_lifecycle::LifecycleNode` now drives, reads and binds its callbacks to its own node's machine. Before, with two managed nodes, its transitions and state reads failed as not initialized.
