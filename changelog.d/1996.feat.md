C++ API: the service-client future takes upstream's verbs, so the stock
rclcpp `minimal_client` ports with zero edited lines (was 15). On hosted
builds (`NROS_CPP_STD`) `client->async_send_request(std::shared_ptr<Request>)`
returns the poll client's `rclcpp::Future`; `future.get()` returns the reply as
an owning `std::shared_ptr<Response>` once it has arrived (it never blocks:
before the reply it logs a refusal and returns nullptr); and
`future.wait_for(duration)` returns `std::future_status`, spinning the executor
while it waits. `future.valid()` and `client->remove_pending_request(future)`
work on every build. A freestanding build refuses `get()` at compile time,
naming `try_take`. Still one request in flight per client (issue 1996).
