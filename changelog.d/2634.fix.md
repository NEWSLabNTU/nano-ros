A parameter declaration the parameter store has no slot for now stops the boot instead of running on the compiled default. In C++, `declare_parameter<T>(name, default)` used to return the default for every refusal but "already declared", so when the store was full a launch or YAML value was lost with no word and the node ran on its code defaults. It now latches the node's error (`NROS_CPP_RET_FULL`) so the entry halts boot. C's `rclc_add_parameter` / `rclc_parameter_declare_*` return `RCLC_RET_FULL` for a full store (it was `RCL_RET_ERROR`), and every language logs a line naming the node, the parameter, the store's capacity and the knob that sizes it: `max_parameters` under `[knobs.params]` in system.toml, `NROS_MAX_PARAMETERS`, or `CONFIG_NROS_MAX_PARAMETERS`. Left unstated, the size is derived when every node in the image declares its parameters under `params:` in its contract (GitHub #4018, issue 2634).
