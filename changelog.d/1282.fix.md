A fresh Zephyr workspace no longer fetches `hal_espressif`, which is 275 MB nothing in the tree consumed — the last of the four vendor HALs issue 1275 measured as unused, and the one held back while the strategy question behind it was open. That question is now settled: **bare-metal esp-hal is the esp32 path, and Zephyr-hosted esp32 is not supported for now.** Nothing that worked stops working — no board, conf, overlay or fixture row ever named an Espressif board through Zephyr, and the Zephyr SDK we provision has never carried an `xtensa-espressif_*` toolchain to link one with — so the dead `CONFIG_SOC_SERIES_ESP32C3` Rust-target branch went with it. The decision is reversible; re-adding the module means re-adding a board and a toolchain beside it. Note that `west update` never prunes, so an existing workspace keeps the 275 MB until it is re-fetched.
