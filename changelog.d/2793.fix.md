On a Zephyr board with `CONFIG_NROS_ZEPHYR_STACKS_IN_DTCM`, an image that declares no sched task no longer carries the unused sched-task stack pool in DTCM (65,792 B on the Nucleo-F767ZI). nano-ros now places its DTCM stacks in an output section of its own, which `--gc-sections` can trim, instead of Zephyr's generated DTCM section, which keeps everything placed in it. The Nucleo-F767ZI board no longer turns `CONFIG_NROS_ZEPHYR_SCHED_TASK_STACKS_IN_DTCM` off.
