A Linux level that declares a `real_time` budget and period now runs under a `SCHED_DEADLINE` reservation (runtime = budget, period = period, deadline = the declared one within [budget, period], else the period) on both the C ABI's native level runner and the Rust arm, and the executor hands the level's budget to the kernel instead of enforcing it a second time (issue 2018). Without `CAP_SYS_NICE` the kernel refuses: the port says so once with the `setcap cap_sys_nice+ep` fix and a `deadline budget FAILED` line per level, and the executor enforces the budget. The session-owning level gets no reservation. Each level's policy now lowers onto its own sched context on Linux too, not the executor's default.
