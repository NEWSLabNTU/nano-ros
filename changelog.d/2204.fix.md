A Zephyr Rust image whose board descriptor states a `[board.zephyr] rust_target` different from the triple zephyr-lang-rust compiles it for (on Arm, set by the CPU and `CONFIG_FP_HARDABI`) is now refused at configure time, naming both triples and the descriptor. Before, the mismatch was silent, and `nros setup` installed a target the build never used.
