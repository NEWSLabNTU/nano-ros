A workspace board package that is also on `$NROS_EXTRA_BOARD_PATH` is now one board. The catalog loaded it from the extra path and again as a workspace package, so every image naming it was refused as "ambiguous -- 2 descriptors claim it", both candidates citing the same `nros-board.toml`. A consumer whose hand-written Zephyr app calls `nano_ros_use_board()` on its own board needs the path for that call (the projection runs with the nano-ros tree as its workspace) while the image's configure, run on the consumer's workspace, finds the same package, so one configure could not satisfy both.
