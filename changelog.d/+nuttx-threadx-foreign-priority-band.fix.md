On ThreadX, an application level can no longer be placed at priority 31. The host-socket receive notifier runs there and blocks in a host call, which starves every thread at its priority, so a level at 31 never ran. The ThreadX app pool now stops at 30. The NuttX and ThreadX priority plans now also state the bands of the threads nano-ros does not create (the kernel's work queues and timer thread), and both images print every thread and its priority at boot.
