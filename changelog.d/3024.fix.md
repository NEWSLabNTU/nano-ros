On POSIX hosts (Linux, and NuttX, which runs the same port), a task that states a priority now applies it, and its thread name, from inside the task before its entry runs. The port used to apply both from the creating thread after the task had started, so a task that finished quickly could be gone by then. On a host that may not use real-time scheduling, the one warning the process prints then named the wrong error and left out the `setcap cap_sys_nice` advice.
