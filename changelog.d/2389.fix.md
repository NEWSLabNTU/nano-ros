A zenoh client's connect budget (`[knobs.zenoh.limits] connect_timeout_ms`) now bounds the whole open on the BSD-socket ports (Linux/POSIX, NuttX, Zephyr including native_sim): the TCP connect and each attempt's handshake, not only the retries between attempts. Before, a peer that accepts the TCP connect and never answers held one attempt for zenoh-pico's own 10 s handshake deadline (measured on Zephyr native_sim with a 3 s budget: 10.1 s, now 3.03 s; issue 2389), and a peer that drops the SYN held it for the OS's SYN retries (Linux: 133.1 s, now 3.00 s; native_sim: 136.2 s, now 3.0 s after boot; issue 2437). A failed open also prints `zenoh open: no session with <locator> within connect_timeout_ms=<N>`, naming the budget it gave up under. ThreadX and bare-metal smoltcp get the same bound through a new platform ABI function, `nros_platform_tcp_open_within` (threadx-linux: 135.8 s, now 3.02 s; issue 2438). Platform ports out of tree must implement it. A zenoh client whose router keeps the connection open and stops reading no longer hangs for ever: a TCP write that takes no byte for 5 s (`Z_TRANSPORT_TX_WAIT_BEFORE_CLOSE`, zenoh's own `wait_before_close`) fails, zenoh-pico closes the session (and reconnects), and the console says `zpico: session closed: a write to the router took no byte for 5000 ms ...`. Before, the write blocked holding the transport's TX mutex, so publishers, keep-alives and the lease's close all waited behind it, silently (measured on Zephyr native_sim and Linux: silent for the whole 60-90 s run; after: the line about 14 s after the router stopped reading, including the time to fill the socket buffers). `nros_platform_tcp_send` now waits at most about the socket's timeout and returns the bytes taken, `0` for none; out-of-tree platform ports must follow that contract. Issue 2389 itself stays open until the a53 boot it was filed for is re-run.
