The entity counts an image needs (how many publishers, subscriptions, queryables, liveliness tokens, pending service calls and large-payload subscribers) are now their own settings under `entity`, separate from the zenoh pools sized from them. State them as `[image.<id>.knobs.entity] max_publishers` (or in a board's `[knobs.entity]`), as `NROS_ENTITY_MAX_PUBLISHERS` in the build environment, or as `CONFIG_NROS_ENTITY_MAX_PUBLISHERS` in a Zephyr project without a `system.toml`; the same for `max_subscribers`, `max_queryables`, `max_liveliness`, `max_pending_gets` and `max_large_subscribers`. `-1` still means "derive it from what the image declares".

The zenoh pools (`zenoh.max_publishers` and its five siblings) are no longer settings: `nros` derives each from the matching `entity` count, raising a count of 0 to 1 for the four pools that size a fixed array, so an image that declares no publishers still builds. Writing `[image.<id>.knobs.zenoh] max_publishers` (or one of the siblings) is refused with a message naming `[image.<id>.knobs.entity] max_publishers`.

The old names are refused with a message naming the new one: the Zephyr symbols `CONFIG_NROS_MAX_PUBLISHERS`, `CONFIG_NROS_MAX_SUBSCRIBERS`, `CONFIG_NROS_MAX_QUERYABLES`, `CONFIG_NROS_MAX_LIVELINESS`, `CONFIG_NROS_MAX_PENDING_GETS` and `CONFIG_NROS_MAX_LARGE_SUBSCRIBERS` (now `CONFIG_NROS_ENTITY_MAX_*`), the build variables `NROS_MAX_PUBLISHERS` and its five siblings (now `NROS_ENTITY_MAX_*`), and `-DNROS_OVERRIDE_ZENOH_MAX_PUBLISHERS` and its siblings (now `-DNROS_OVERRIDE_ENTITY_MAX_*`). Values are unchanged.
