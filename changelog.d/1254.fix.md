`just zephyr setup` registers the Zephyr SDK from the store again when the workspace already exists. The registration step built the legacy in-checkout path `scripts/zephyr/sdk/zephyr-sdk-<v>`, which does not exist on a store-provisioned host or in a fresh worktree, so it reported nothing to do and left the SDK unregistered. It now asks `scripts/lib/zephyr-sdk.sh resolve`, and the new `check-zephyr-sdk-path-asked` gate refuses a hand-built copy of that path (issue 1254).
