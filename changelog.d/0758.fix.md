`CONFIG_NROS_SNTP_EPOCH` now works for single-executor Zephyr images and reaches the wall clock. Two gaps kept an acquired epoch from any node: only the tiered entries (`zephyr_run_tiers.c`, `entry_tiers.rs`) called `nros_zephyr_epoch_acquire_configured`, so an image entering through `ZephyrBoard::run_components` or `nros_board_rtos_run_components` never asked for one; and the Zephyr port's `nros_platform_time_now_ns` returned a hard 0, so `rclcpp::Clock().now()`, `nros_clock_get_now_ns(NROS_CLOCK_SYSTEM_TIME)` and `nros_core::Clock::system()` never saw the epoch even when it was there. Both entries now acquire it after network-up and before the first component, and the wall clock returns it (still 0 until one is acquired).
