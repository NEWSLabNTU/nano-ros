The post-link stack-floor check no longer fails with a Python `RecursionError` on an image whose call graph is deeper than about a thousand calls (seen on `s32z270-rtu0-zephyr`). The walk is iterative now, so it also answers the same whether its walk orders run in parallel worker processes, as under `nros build`, or one after another, as under a bare `cmake --build` — which is why a failed build used to pass when re-run.
