`nros fix` now moves an `[image.<id>] env` (or `[image_defaults] env`) row that sets a registry knob to the image's knobs table, `[image.<id>.knobs.<group>]`, converting a retired spelling's unit on the way: `NROS_FREERTOS_HEAP_KB = "64"` becomes `heap_bytes = 65536`. Before, it renamed a retired spelling in place and kept the number: for `NROS_FREERTOS_HEAP_KB = "64"` it wrote `NROS_MEMORY_HEAP_BYTES = "64"`, 64 bytes where 64 KiB was meant, and the build then refused the rewritten row because it still set a registry knob through `env`. It also rewrites `board = "native"` or `"posix"` to `"linux"`. Each of these is now refused at its line with its own code (NROS-0012, NROS-0013). A `framework` the board cannot boot is refused at the image's line and at the board definition's `frameworks` line (NROS-0014), and several refusals about one image print as one group.
