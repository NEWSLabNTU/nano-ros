A string or array parameter a node declares in its code now needs its capacity stated, as one declared under `params:` in the contract already did. The parameter store is sized from what each node's code declares, so a node that declares one in code now makes the build need its length: `NROS_MAX_STRING_VALUE_LEN` for a string, `NROS_MAX_ARRAY_LEN` for a bool, integer or double array, both `NROS_MAX_STRING_VALUE_LEN` and `NROS_MAX_STRING_ARRAY_LEN` for a string array, and `NROS_MAX_BYTE_ARRAY_LEN` for a byte array. A project that built before can stop at `nros-params`'s build script on upgrade with an error of the form ``nros-params: parameter `<name>` on node `<node>` is declared with a type that needs it, so the parameter store needs NROS_MAX_STRING_VALUE_LEN, and NROS_MAX_STRING_VALUE_LEN is stated nowhere.`` To fix it, state each length the message names for the image, for example `[image.<id>.knobs.params] max_string_value_len = 64` and `max_array_len = 16` in `system.toml`. A board can state them in its own `[knobs.params]` instead. No code changes.
