The Zephyr `rust/action-server` example now reports what it actually did. It says `Goal succeeded` only when `complete_goal` returned `Ok` and logs the error otherwise — printing the banner over a discarded `Result` is the same shape issue 0902 measured from the client side, where a goal is accepted, executed and then never answered while the transcript reads as a success. It also reports its zenoh reply-slot refusal count (`reply-slot: refusals=<n>`) on a cadence, so the one number that separates an exhausted reply table from a slow image is readable from the image itself rather than inferred from the client; a build with no zenoh shim prints `n/a no-zenoh-shim` instead of a misleading zero.
