`nros configure --migrate` now also rewrites a project's contracts (`*.contract.yaml`) and `system.toml` files from spellings the contract checker no longer reads, printing every key it changes. A project scaffolded by an earlier release, whose talker contract writes `rate_hz: 1`, configures again after one run of it. When configure stops on an old spelling, its message now leads with `nros configure --migrate` and names the source file to change, and no message tells a user to run `play_launch migrate`, which nano-ros does not ship. `nros doctor` reports a contract still in an old spelling. With an installed SDK it also accepts this release's vendored sources and host tools into the project's `nros-sdk.lock`, as `nros update --source` / `--tool` would, so a project last built by an earlier release no longer stops with "resolved off the pin set". `nros update --help` now says what each flag does with an installed SDK.
