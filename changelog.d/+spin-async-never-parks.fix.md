`Executor::spin_async()` no longer blocks its async runtime's thread: each poll runs one non-blocking `spin_once(Duration::ZERO)` pass instead of `spin_once(1 ms)`, so a sibling future on a single-threaded runtime (tokio `current_thread`, Embassy) is no longer held up to 1 ms per cycle. It still wakes itself on every poll, so it remains a busy loop — and with the 1 ms park gone it now uses a full core when idle — until it is wired to the executor's readiness notifier (issue 2144) and next deadline (issue 2143). The book no longer calls it waker-driven (issue 2145).
