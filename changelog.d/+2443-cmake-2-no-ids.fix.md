The CMake configure refusals of the PX4, NuttX, Cyclone DDS and Zephyr integrations (a generated header that does not pair with its archive, an archive carrying a backend the module did not ask for, a missing NuttX tree or cargo dep-info file, a pinned Cyclone descriptor cap that is too small, an idlc that cannot run, an image mixing two nano-ros checkouts or using another checkout's Zephyr SDK, a missing Cyclone type-support module, an unreadable baked domain, a missing bringup, and a bringup that disagrees with the image Kconfig rendered) no longer cite internal design ids. Several now also say how to fix them: pass `-DNUTTX_DIR`, unset the descriptor-cap pin, or restore the Cyclone DDS CMake directory.
