`nros setup` (and `nros locate`, `nros sdk-path`, `nros sdk-front`) run from any subdirectory of a nano-ros checkout now reads that checkout's `nros-sdk-index.toml` instead of the store's cached copy, which nothing refreshed; `--index` and `NROS_INDEX_URL` still outrank it, and a host with no checkout is unchanged. A cached index this `nros` cannot load is refetched rather than served, and a refusal over an invalid index names the way out for where that file came from (`NROS_INDEX_REFRESH=1` for the store copy, `--index` for an explicit one, the checkout's `check-source-refs.py --write` only for the checkout's own).
