A generated Zephyr C/C++ application now adds its packages in dependency order (each after the workspace packages it `<depend>`s on, ties by name), the order the CMake road already used. It used to add them by name, so a package whose standalone fallback adds its own dependency could run first and fail the configure with "another target with the same name already exists". A `<depend>` cycle among an image's packages is now refused, naming the packages on it.
