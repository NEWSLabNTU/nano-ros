The MPS2-AN385 bare-metal board boots two entry frameworks, chosen per image. Its descriptor lists `frameworks = ["owned-spin", "rtic"]` and `entry_types = { owned-spin = "Mps2An385", rtic = "RticMps2An385" }`, so `[image.<id>] board = "mps2-an385-baremetal"` with no `framework` builds the direct-exec entry as before, and adding `framework = "rtic"` builds the `#[rtic::app]` entry over the RTIC board type. `nros::main!` reads the list from the image's board descriptor (the `NROS_BOARD_TOML` file `nros build` names), the same file the CLI reads, so the two cannot disagree. `board = "rtic-mps2-an385"` still builds the RTIC entry until that word retires.
