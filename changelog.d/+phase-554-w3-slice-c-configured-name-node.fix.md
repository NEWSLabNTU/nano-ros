An image that declares no node of its own is now announced as one real node named after the executor's configured name, created the first time it needs one: when it creates an entity on the executor, or at its first spin if diagnostics, parameter services or a sim-time source are waiting. The first node to exist is the image's primary node. An executor-level entity created before any node therefore makes the configured name the primary node, and a node built afterwards comes second. Opening an executor with an empty node name is refused, and the error names `ExecutorConfig::node_name`. An executor built from a bare session is named `node`, the same default `ExecutorConfig` uses.
