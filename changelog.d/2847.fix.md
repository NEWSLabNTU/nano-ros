On a Zephyr board with deferred logging (every board except native_sim), a thread's log message no longer disappears when a burst fills the log buffer: the thread now waits up to 10 s for the logging thread to make room. A console line you wait for, such as the network's `IPv4 address:` line or `nros: core pin observed`, used to vanish under a boot-time burst. Messages logged from an interrupt can still be dropped. To restore the old behaviour, set `CONFIG_LOG_BLOCK_IN_THREAD=n` in your application's conf.
