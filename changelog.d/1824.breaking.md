nros-c and nros-cpp no longer write their per-build config headers to `$CARGO_TARGET_DIR/nros-{c,cpp}-generated/` or the `.h.stamp` beside them; the only copy is the build script's `$OUT_DIR`. A cargo dependent reads `DEP_NROS_{C,CPP}_CONFIG_INCLUDE`; any other build runs cargo under `scripts/build/cargo-out-dir-headers.py --dest <dir>` and asks `nros locate artifact <c|cpp>-include --placed-dir <dir>`, which now refuses a header lookup without `--placed-dir`. A script that compiled against the target-dir copy must move to one of the two. ([#1824](https://github.com/NEWSLabNTU/nano-ros/issues/1824))
