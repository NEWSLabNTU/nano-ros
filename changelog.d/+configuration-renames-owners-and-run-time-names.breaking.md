More settings are renamed so that each one carries the word of the component it configures, and the old names are refused with a message that names the new one. As before, the environment variable and the Kconfig symbol follow the key (`params.max_parameters` is `NROS_PARAMS_MAX_PARAMETERS` and `CONFIG_NROS_PARAMS_MAX_PARAMETERS`), and the refusal applies wherever the old name is written: `system.toml`, a board or platform `[knobs]` table, the build environment, a Zephyr conf file or `-DCONFIG_`, and `-DNROS_OVERRIDE_`. The renames, old to new:

- Parameters: `params.param_events_depth` to `params.events_depth`, `[knobs.param] service_inbox_bytes` and `service_inbox_depth` to `[knobs.params] service_inbox_bytes` and `service_inbox_depth`. The variables of `params.max_parameters`, `params.max_array_len` and `params.max_string_array_len` gain the `PARAMS_` word: `NROS_MAX_PARAMETERS` to `NROS_PARAMS_MAX_PARAMETERS`, `NROS_MAX_ARRAY_LEN` to `NROS_PARAMS_MAX_ARRAY_LEN`, `NROS_MAX_STRING_ARRAY_LEN` to `NROS_PARAMS_MAX_STRING_ARRAY_LEN`, `NROS_PARAM_EVENTS_DEPTH` to `NROS_PARAMS_EVENTS_DEPTH`, `NROS_PARAM_SERVICE_INBOX_BYTES` and `_DEPTH` to `NROS_PARAMS_SERVICE_INBOX_BYTES` and `_DEPTH`.
- The network stack's variables use `NET_`: `NROS_SMOLTCP_MAX_SOCKETS` to `NROS_NET_MAX_SOCKETS`, `NROS_SMOLTCP_MAX_UDP_SOCKETS` to `NROS_NET_MAX_UDP_SOCKETS`, `NROS_SMOLTCP_CONNECT_TIMEOUT_MS` to `NROS_NET_CONNECT_TIMEOUT_MS`, `NROS_SMOLTCP_SOCKET_TIMEOUT_MS` to `NROS_NET_SOCKET_TIMEOUT_MS` (the `[knobs.net]` keys are unchanged).
- `[knobs.graph] max_entities` to `[knobs.zenoh] graph_max_entities` (`NROS_GRAPH_MAX_ENTITIES` to `NROS_ZENOH_GRAPH_MAX_ENTITIES`).
- Zephyr Kconfig: `CONFIG_NROS_ZENOH_LOCATOR` to `CONFIG_NROS_LOCATOR`, `CONFIG_NROS_CYCLONE_DOMAIN_ID` to `CONFIG_NROS_CYCLONEDDS_DOMAIN_ID`, `CONFIG_NROS_CYCLONE_CONFIG_XML` to `CONFIG_NROS_CYCLONEDDS_CONFIG_XML`, `CONFIG_NROS_EPOCH_FROM_ZENOH` to `CONFIG_NROS_ZENOH_WALL_CLOCK_EPOCH`, `CONFIG_NROS_EPOCH_FROM_ZENOH_INTERVAL_MS` to `CONFIG_NROS_ZENOH_WALL_CLOCK_EPOCH_INTERVAL_MS`, `CONFIG_NROS_ZEPHYR_TASK_STACK_SIZE` to `CONFIG_NROS_ZEPHYR_TASK_STACK_BYTES`, `CONFIG_NROS_ZEPHYR_SCHED_TASK_STACK_SIZE` to `CONFIG_NROS_ZEPHYR_SCHED_TASK_STACK_BYTES`, `CONFIG_NROS_ZEPHYR_LEVEL_WORKER_FRAME` to `CONFIG_NROS_ZEPHYR_LEVEL_WORKER_FRAME_BYTES`, `CONFIG_NROS_CONSOLE_WHOLE_LINES_BUFFER` to `CONFIG_NROS_CONSOLE_WHOLE_LINES_BUFFER_BYTES`, `CONFIG_NROS_EDMA_WARM_RESET_QUIESCE` to `CONFIG_NROS_ZEPHYR_EDMA_WARM_RESET_QUIESCE` and `CONFIG_NROS_PARAM_STORE` to `CONFIG_NROS_PARAMS_STORE`. Values are unchanged. The old alias `CONFIG_NROS_ZEPHYR_TIER_STACK_SIZE` is removed: set `CONFIG_NROS_ZEPHYR_SCHED_TASK_STACK_BYTES`. `CONFIG_NROS_TRANSPORT_SERIAL` is removed: state the image's transport as serial in `system.toml`, or set `CONFIG_NROS_ZENOH_LINK_SERIAL=y` in a project without one. A Zephyr project without a `system.toml` that still sets an old symbol now fails to configure with a message naming the new one.
- Variables read when an image runs: `XRCE_SERIAL_BAUD` to `NROS_XRCE_SERIAL_BAUD`, `NROS_CYCLONE_MATCH_TIMEOUT_MS` to `NROS_CYCLONEDDS_MATCH_TIMEOUT_MS`, `NROS_RMW_CYCLONEDDS_SKIP_PREFIX` to `NROS_CYCLONEDDS_SKIP_PREFIX`. A hosted image started with an old one set stops at startup, naming the new one.
- Build variables: `ZPICO_MULTICAST_TRANSPORT` becomes the setting `zenoh.multicast_transport` (`[image.<id>.knobs.zenoh] multicast_transport = true`, or `NROS_ZENOH_MULTICAST_TRANSPORT=1`), `NROS_ZPICO_DEBUG` becomes `NROS_ZENOH_DEBUG`, and `ZPICO_NO_SMOLTCP` becomes `NROS_ZENOH_NO_SMOLTCP`, which `nros` sets from `transport = "serial"`.
- The domain, locator and node name are never read from the build's environment any more. They come from `system.toml` (`domain_id`, `locator`), carried to the build as `NROS_ENTRY_DOMAIN_ID`, `NROS_ENTRY_LOCATOR` and `NROS_ENTRY_NODE_NAME`. A build with `NROS_DOMAIN_ID` set stops, naming `[system] domain_id`. `NROS_LOCATOR` and `NROS_NODE_NAME` stay what a hosted image reads when it runs; a build that finds them set prints a note and goes on.
