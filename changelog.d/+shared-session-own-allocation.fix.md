A Rust executor that shares its session with sched-task executors (`session_handle`) now keeps that session in its own allocation, so the pointer each sched task holds stays valid while the owner keeps spinning. `Executor::session_handle` and `Executor::session_ptr` return `Option`: `None` when the session may not be shared, which happens only if that allocation failed, and the C++ `nros_cpp_executor_session_handle` then returns NULL.
