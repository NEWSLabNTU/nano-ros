ros-launch-manifest v0.3.11 and play_launch 0.28.0 (phase 536 W3): a `system.toml` that still writes `[tiers.<name>]` or `[[component]] group_tiers` is refused, by nano-ros's own reader and by the resolver, with a message naming `[tasks.<name>]` / `group_tasks` and `play_launch migrate <system.toml> --write`, which rewrites the file. The SystemModel is schema 5: its task table is `execution.tasks`; a model saved before (schema 4, `execution.tiers`) still loads and builds the same image.
