Executor: a subscription with a status-event callback is now asked `has_data` on every spin, not only after an arrival. Both backends that carry subscription status events poll them there (zenoh: deadline, liveliness and matched; Cyclone DDS: its `take_event` drain). The executor used to skip that call for a wake-attributed subscription with nothing new to read, so once the last publisher left, the matched count never fell, the liveliness count never dropped and `RequestedDeadlineMissed` never fired. A subscription with no status callback is still read from its arrival bit, so an idle executor makes no extra calls. The zenoh shim's `take_serialized` now drives the same three polls as `has_data`, so a caller that only takes sees matched and liveliness changes too. The interop cell `native-qos-event-c-zenoh-bidir` now asserts the subscription-side fall against stock ROS 2 (issue 2060).
