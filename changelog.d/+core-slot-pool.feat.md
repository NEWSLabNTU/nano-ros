nano-ros has a core slot pool for device jobs: fixed-size slots in two classes, `small` and `large`, that code claims, hands to a job, and releases where the job ends, including from an interrupt handler. A claim with no free slot is refused and counted; it never blocks or allocates. Size each class with `[image.<id>.knobs.slot]` `small_count` / `small_slot_bytes` and `large_count` / `large_slot_bytes`. Both counts default to 0, so an image that does not use the pool reserves nothing.
