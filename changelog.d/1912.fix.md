The submodule-pin gate no longer reports a REWIND for a commit that moved no
pin. In CI it used to compare against main's live tip, so a push gate that ran
after a later pin bump had merged saw that bump as a rewind. The baseline is now
the commit under test's own: the push's `before`, the merge group's base, the
pull request's base, or the commit's first parent. A local `just check fast`
uses the branch point with `origin/main`. `scripts/ci/pin-baseline.sh` is the
one place this is decided.
