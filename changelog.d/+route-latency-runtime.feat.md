A new runtime contract rule, `route-latency-runtime`, judges an input-triggered node path from the take of its trigger input to the dispatch that publishes its output, against the path's `max_latency`. `max-latency-runtime` times one dispatch, so a path that reads its input on a timer tick could exceed its budget by waiting for a late tick while every callback stayed inside it. The verdict is recorded (rule code 10 in `NROS_VIOLATION_RECORD` and the trace markers; the record layout is unchanged) and has no action. Generated C and C++ entries bake the route's trigger topic and budget into the monitor rows; `NROS_CPP_MONITOR_ROW_STORAGE` is now 128 on a 64-bit host (still 64 on a 32-bit target).
