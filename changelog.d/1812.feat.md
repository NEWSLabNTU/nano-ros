`param-services` no longer needs `alloc`: an image whose build knows it carves a parameter store (`NROS_PARAM_STORE=1`, or parameters declared in the contract) now carves the service state, the shared request/reply buffers and a staging slot for incoming values from the executor backing, so `ros2 param` works on an image with no heap. A remote `set_parameters` no longer holds a ~8.5 KiB parameter value on the stack (measured 26 KiB -> 352 B per request in release). A heap-free build with no carved store is refused at compile time, naming `NROS_PARAM_STORE`.
