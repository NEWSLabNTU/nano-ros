An image whose code was watched declaring no parameters now sizes its parameter store for the one parameter the runtime seeds, rather than the default 32-parameter store, even with no `params:` in its contract. On a small board that is tens of kilobytes of RAM. A build that did not watch every node's declarations keeps the default, as does a node that allows undeclared parameters, and `nros build --explain-sizing` now says when a parameter store keeps its default bounds and how to state them.
