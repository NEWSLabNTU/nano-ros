The post-link stack-floor check now works on a fat-LTO image whose crate names are long, and on a project that pins its own Rust toolchain. Before, it failed with FileNotFoundError when rustc had shortened a bitcode file name, and it compiled the bitcode with the llc of rustup's default toolchain instead of the toolchain that wrote it. That llc fails with "Not an int attribute" when the two LLVM versions differ. The check now finds each module by its codegen unit. It takes llc and llvm-dis from the toolchain the bitcode names as its producer, and refuses one of a different LLVM version rather than running it.
