Each preemption level now has its own scheduling context, lowered from its tier's policy (`Executor::set_level_sched_context`, C ABI `nros_cpp_level_set_sched_policy`, Rust `ExecutorNodeRuntime::apply_level_sched_policy`), so a level's budget is charged to that level and not to the executor's default context every level shared (issue 2018). On NuttX a level's budget has one enforcer: when the kernel accepts `SCHED_SPORADIC` for the level's thread the executor hands its cooperative budget to the kernel (`Executor::defer_budget_to_kernel`) instead of throttling the level a second time, and without the kernel's server the executor enforces the same budget. The runner says which (`level budget ... enforced by the KERNEL|EXECUTOR`), and the Rust arm now reports a kernel throttle the way the C runner does.
