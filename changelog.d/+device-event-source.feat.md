A device can now be an executor event source. `Executor::register_device` claims a callback slot for a device's continuation and returns a `Completion` that the device's port signals when a job is done: `signal()` from a thread, or `signal_from_isr()` from an interrupt handler. The continuation runs at the priority of the sched context the slot is bound to, ahead of lower-priority ready callbacks, and LET mode samples completions at the start of the spin. `CompletionCell` holds one completion where an interrupt handler can reach it. From C, `nros_executor_register_device` in the new extension header `<nros/device_hook.h>` does the same and returns an `nros_completion_t`, which a port signals with `nros_completion_signal` or, from an interrupt handler, `nros_completion_signal_from_isr`. A registered device is counted by the census, and a declared `device` entity is counted in the image's callback slots and executor arena.
