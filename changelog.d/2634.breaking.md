In C++, `declare_parameter<T>(name, default)` now stops the boot when the parameter's launch or YAML value has another type than `T`. It used to return the code default with no message, so the node ran on a value its launch file did not state. The most common case is an integer written for a double: `kp: 1` for a parameter declared `double`. The boot log names the node, the parameter, the value and the fix, for example `parameter "kp" is declared double but the launch value is the integer 1; write 1.0 in the YAML.` Check your launch and YAML files for integers written where the code declares a double before you upgrade. This matches upstream rclcpp, which throws on the same mismatch (GitHub #4018, issue 2634).
