A FreeRTOS image that runs preemption levels now builds its kernel with `configUSE_TIME_SLICING 0` (RFC-0108 D6, issue 2017), so a level is never sliced against an equal-priority task in the middle of a callback; images without levels keep the kernel default. The per-image input is `NROS_FREERTOS_LEVEL_IMAGE`: a tiered C/C++ entry sets it through `nano_ros_entry`, a multi-tier Rust schedule through the board crate's new `level-image` feature. A tiered FreeRTOS entry refuses to build against a slicing kernel (a host with its own `FreeRTOSConfig.h` can state `NROS_FREERTOS_ALLOW_TIME_SLICING`), and the level runners print the kernel's setting at boot.
