`nros::InitError::LaunchParseFailed` is removed. Nothing ever returned it: it waited on an in-process launch-file parse that will not be built, because launch content reaches an image at build time (`nros sync` resolves the launch tree into the SystemModel and the generated entry installs it). A `match` that names the variant drops that arm. The `init_with_launch*` docs (Rust and C++) no longer describe a `NROS_RUNTIME_OVERLAY` sidecar or an `nros launch` verb — neither exists (issue 1917).

`nros::ContextSource::Launch` is removed as well, and `nros::init_with_launch_auto()` / `nros::init_with_launch(path)` now report `ContextSource::Env` and are deprecated. Both read the environment exactly as `nros::init()` does and read no launch file, so `Launch` claimed something that never happened — while `nros::main!(launch = …)`, the entry that does install launch content, reported `Env`. Replace `nros::init_with_launch_auto()` with `nros::init()`; replace `nros::init_with_launch(path)` with `nros::init()`, checking `path.exists()` yourself if you relied on that. Projects scaffolded by `nros new` before this release call `init_with_launch_auto()` and will see the deprecation warning. The C++ `rclcpp::init_with_launch_auto` / `init_with_launch` are unchanged.
