A Zephyr build dir now follows its application's config directory: a `boards/<board>.conf` (or overlay) added after the first configure is merged, and one deleted no longer fails every later configure with `kconfig.cmake: File not found`. Zephyr discovers those files only while `CONF_FILE` is unset and then caches what it found, so the first configure's list stuck and only a pristine build recovered. The nano-ros module now drops a discovered value before Zephyr's discovery runs, so discovery runs again on every configure, and adding or deleting a fragment re-runs cmake on a plain build. A `-DCONF_FILE` you pass is still a choice and still suppresses discovery. Existing build dirs recover with `cmake <dir>` or the next `nros build`. ([#2374](https://github.com/NEWSLabNTU/nano-ros/issues/2374))
