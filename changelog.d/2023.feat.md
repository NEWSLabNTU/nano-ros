C++ and Rust nodes now publish `/parameter_events`
(`rcl_interfaces/msg/ParameterEvent`, `rmw_qos_profile_parameter_events`), as C
already did and as rclcpp and rclrs do. A node whose parameters are served
(`Node::start_parameter_services()` in C++, `[param_services]` or
`Executor::register_parameter_services` in Rust) publishes a start-up event
naming the parameters it already holds, then one event per declare, set and
undeclare, with `node` set to its fully qualified name. All three languages go
through one core path. One publisher per executor serves every node: the
`param_services` capability now costs one more publisher slot and liveliness
token, and the derived pool sizes count it. rclc's
`notify_changed_over_dds = false` still turns a C node's events off. An event too
big for `NROS_PARAM_SERVICE_BUFFER_SIZE` is dropped with an error log, never
truncated. Subscribing to other nodes' events (`rclcpp::ParameterEventHandler`)
is not offered yet (issue 2024).
