`nros build` now checks a threadx-linux image's app stack against the peak the image was measured at, plus the table's margin, and fails naming `NROS_MEMORY_APP_STACK_BYTES` when the stack is below it. A host image is not walked, because its deepest paths run through the host C library, so the check reads an `[[observed]]` row marked `unwalked` in `config/stack-floors.toml`. An image with no such row is reported as not checked, with how to measure it.
