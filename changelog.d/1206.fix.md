`nros build` now builds every image it planned. `--all`, several positional images and a `[system] default_images` naming several each produce N plans, and the driver loop execed inside itself — `exec` never returns, so image 1 was built, images 2..N were never reached, and the command exited 0 with image 1's verdict and one announcement line on the terminal (measured on `examples/workspaces/rust`: two images asked for, one artifact, `rc=0`). RFC-0065 D1's `exec` is spent on the LAST plan, so a single-image build is unchanged in every respect; the earlier plans run as children with **inherited** stdio — no pipe anywhere, so diagnostics, colour and Ctrl-C behave as before — and a multi-image run prefixes each announcement `[i/N]`, which is the only progress report available once the last plan replaces the process.
