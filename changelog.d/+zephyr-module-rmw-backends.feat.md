An RMW backend kept outside nano-ros can now bring its own Zephyr code. Its `nros-rmw.toml` states `[rmw.zephyr] module = "zephyr"`, naming the directory in the package that holds its Zephyr `module.yml`, and a Zephyr image with that backend as its `rmw` gets the package's module added to the build and the backend added as a choice of RMW, with no change to nano-ros or to the application. A backend built over one of nano-ros's own Zephyr backends still states `[rmw.zephyr] module_backend`, which may now also name a backend that is its own module. A Zephyr image whose `rmw` is chosen in `system.toml` now refuses a conf file or `-DCONFIG_NROS_RMW_*` that selects a different RMW, instead of silently letting the last setting win. The RMW choices in the Zephyr and NuttX menus now list the backends in alphabetical order.
