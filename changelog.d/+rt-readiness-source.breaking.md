A platform port must now define `nros_platform_wake_park_handles_us`. It parks the executor on its wake object and on RMW sessions' OS handles (RFC-0113 D3, phase-521 W3). A port without file descriptors returns `-1`, as `examples/linux/c/custom-platform` does. The RMW vtable gains an optional `readiness_source` slot, through which a session reports its readiness as Notify (its wake callback) or Waitable (a file descriptor). On POSIX and NuttX, a tier whose session is Waitable now parks in `ppoll` and drains the transport without blocking, instead of waiting inside its receive. A net provider must also define `nros_platform_udp_readiness_handle`, which returns the socket's file descriptor, or `-1` where the stack has none. XRCE over UDP or POSIX serial reports that descriptor, so a guard trigger on an XRCE tier is dispatched in about 90 us instead of within a 10 ms slice.
