On 32-bit Arm bare-metal targets built with arm-none-eabi (FreeRTOS on mps3-an536 or s32z270, for example), CycloneDDS no longer misreads the QoS policies stored as enums. The toolchain stores those enums in one byte, and Cyclone read and wrote four. Creating a reader or writer could then fail with `rmw_ret error`, depending on leftover heap contents: about one boot in eight lost its parameter services. The same fault misread the `presentation` policy's flags, and it wrote past those fields when parsing a remote endpoint's QoS. AArch64 and hosted targets were not affected.
