Every enum in the RMW backend C ABI headers (`rmw_event_type_t`, `rmw_qos_compatibility_type_t`, `rmw_endpoint_type_t`, `rmw_network_flow_endpoint_t`'s protocol fields and the rest) is now `int`-sized on every target. On arm-none-eabi these enums used to be one byte in C while the Rust side treated them as four, so `rmw_qos_profile_check_compatible` wrote past a C caller's verdict variable and `rmw_network_flow_endpoint_t` had different layouts on the two sides. Each enum gains a `*_FORCE_INT_WIDTH_` enumerator that is never a real value, and the headers assert the width at compile time. A C or C++ RMW backend built for an ARM EABI target must be rebuilt against the new headers; a `switch` over one of these enums without a `default:` needs a case for the new enumerator to stay `-Wswitch` clean.
