A Zephyr leaf whose board package carries its own `prj.conf` now gets its image's `os_config` fragments too. The module hook read the CLI's answer as a cmake list, so the `;` joining the board's conf to the image's split the value and the image's fragments were dropped without a word -- on a board like `xiao-rp2350` an image with `os_config = ["prj-serial.conf"]` linked with no zenoh link at all. Every configure-time reader of `nros` CLI output now reads it line by line, and a line it cannot attribute, or a conf entry that is not a file, stops the configure instead of being skipped. The `-DEXTRA_CONF_FILE` workaround is no longer needed. ([#2200](https://github.com/NEWSLabNTU/nano-ros/issues/2200))
