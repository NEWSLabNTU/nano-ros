`nros setup <board> --sudo` (and `--workspace --sudo`) now installs the OS packages the board's plan asks for — its tools' and `[source.*]`s' `system = [..]` — before anything is fetched, through the same install code `--tool --sudo` and `--system --sudo` use. A printed ask names the exact `nros setup … --sudo` line for the path that printed it instead of a generic "(or re-run with --sudo)", which was shown on `nros setup <board>` while that path refused `--sudo`. `--sudo` with a selector that installs nothing from the OS (`--list`, `--licenses`, `--build-sources`, `--source` alone, or no selector) is refused with the four lines that take it, where `--list --sudo` and `--licenses --sudo` used to exit 0 (issue 2099).
