On Zephyr, the wall-clock source is now resolved after every component has registered and before anything spins. In an image with several sched tasks, every task waits at its first spin until boot has resolved the clock, so no message is stamped before it, and a `zenoh-hlc` source can hear a sample on any task's subscriptions. Timers start counting when that wait ends, so a slow resolution (an SNTP source with no server, for example) is never reported as missed periods or overruns. A task that never finishes its setup within 30 s fails the boot, naming it. `Executor::restart_timing` (C: `nros_cpp_executor_restart_timing`) re-seeds an executor's timing for code that waits between setup and its first spin.
