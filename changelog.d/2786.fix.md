A Zephyr conf fragment that sets `CONFIG_NROS_CAPABILITY_ROSOUT`, `CONFIG_NROS_CAPABILITY_SIM_TIME` or `CONFIG_NROS_CAPABILITY_PARAM_SERVICES` is now refused at configure, naming the file, the line and `node_interfaces` in `system.toml` as the key that owns it. The build sets those symbols from the image's node-interface selection after every conf file, so the fragment's value used to be dropped without a word.
