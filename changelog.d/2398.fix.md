A generated PX4 module built for NuttX now refuses to configure when a thread it runs nano-ros on has less stack than the executor's floor. Before, PX4's stock sizes built cleanly and overflowed at run time: the module's main task gets a 2048 B `STACK_MAIN` and `wq:rate_ctrl` gets 3150 B, against a 3808 B floor on fmu-v6x. The refusal names the knob to raise: `STACK_MAIN` on `nros_px4_add_module`, or `CONFIG_WQ_<Q>_STACKSIZE` in the board's `.px4board`. SITL builds are unaffected.
