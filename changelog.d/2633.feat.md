The image's CAN frame device now reaches `nros_platform_can_open(can, NULL, ...)`: on a `linux`, `freertos-posix` or `threadx-linux` image the board decodes `[image.<id>.can] device` from the image's network at boot (cargo road), and a C or C++ entry on one of those boards gets a generated hand-off and the SocketCAN backend linked when its image names a device (cmake road). Before, `open(NULL)` on a host board returned `NROS_PLATFORM_CAN_ENODEV` and only a device named in code opened. `just linux test-can-image-device` checks both roads against a SocketCAN interface.
