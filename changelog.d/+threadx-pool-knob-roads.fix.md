A changed `[knobs.memory] heap_bytes` now rebuilds what it sizes: the build scripts that resolve memory knobs watch their environment, so an incremental build no longer keeps the old ThreadX byte pool. And a threadx-linux or threadx-riscv64 image may now state `[image.<id>.knobs.threadx] byte_pool_bytes`, the knob every byte-pool message names; it was refused as a knob of a package the image does not link.
