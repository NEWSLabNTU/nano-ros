`nros-toolchain.toml` can pin one commit or a local checkout, beside a
release. `git = "<url>"` with `rev = "<40-hex sha>"` (spelled as in a cargo
git dependency) makes the first command fetch that commit into
`~/.nros/toolchains/git-<rev>/` and build it with the tree's own
`scripts/bootstrap.sh`; `path = "<dir>"` runs that checkout's own CLI. A
branch, tag or short sha is refused, since none of them names one commit.
The store build is a clean clone, so its stale-CLI check passes without
`NROS_SKIP_STALE_CHECK`, and `nros toolchain gc` keeps a pinned commit. A
`version` pin works as before.
