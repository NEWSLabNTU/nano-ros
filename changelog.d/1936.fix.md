A C++ image cross-compiled with a GCC older than 11 — such as Ubuntu 22.04's `gcc-arm-none-eabi` 10.3 — is now refused at CMake configure time, naming the pinned toolchain and `nros setup --tool arm-none-eabi-gcc`. Before, it failed partway through the build with `'std::this_thread' has not been declared`, because GCC 10's bare-metal libstdc++ does not provide it. C-only images are not refused; they still get the existing warning.
