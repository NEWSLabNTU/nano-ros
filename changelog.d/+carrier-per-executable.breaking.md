A registered component's firmware or program is now named for its `EXECUTABLE`, not for its package, as `rclcpp_components_register_node` names one executable per node. A package that registers `nros_components_register_node(... EXECUTABLE talker DEPLOY threadx)` now produces `talker` where it used to produce `<package name>`, so scripts, flash commands or run lines that load the old name need the new one. A package may now register several components under different `EXECUTABLE` names, and on NuttX, ThreadX, FreeRTOS and native each one builds as its own firmware or program. Registering two components under the same `EXECUTABLE` is refused. On Zephyr a package still builds one program, and a second registration is refused with a message saying to split the package. Rebuild existing build directories after upgrading.
