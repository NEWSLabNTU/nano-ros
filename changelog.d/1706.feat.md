On the cargo and cmake roads, an image whose bringup declares `param_services`, or whose launch file seeds a `<param>`, now carves its parameter store from the executor backing. It no longer asks the RTOS heap for one 280 KB allocation, so a FreeRTOS Cyclone C++ image no longer refuses the store at the 640 KiB heap default. The sizing descriptor gained `[params] store` (`declared`, `param_services`, `launch_seed` or `none`). A bringup with no contract still gets a descriptor carrying only that field when it implies a store. An image without parameters builds byte-identically. On a single-package Rust leaf, the axis counts only together with the `param-services` feature on its own `nros` dependency.
