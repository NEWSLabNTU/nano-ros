The boot report carries the platform heap's high-water mark and its capacity (`heap_peak_bytes`, `heap_capacity_bytes`), written by `nros-platform-zephyr` from `nros_platform_alloc` and `nros_platform_realloc` -- the only two places the peak can move -- so a console-less board answers "how much did it need" after a halt; `just check heap-headroom` (`read-boot-report.py --heap-headroom <dump>`) refuses a dump whose `capacity - peak` is below 24576 and refuses a peak of 0, because an unmeasured image and a measured-and-fine image must not read the same
