A system contract's QoS values and launch arguments are now checked, so a contract that used to be accepted can now be refused. `reliability`, `durability`, `history` and `liveliness` must name a ROS 2 value; a typo such as `transient-local` refuses the contract and names the key, the value and the allowed set. `system_default` and `best_available` are accepted, and an unknown durability no longer matches any other durability. A contract whose arguments fail (a required arg not passed, a value outside its `choices:`, a QoS `$(var …)` outside the set) is now an `error[manifest-args]`; before, the contract was silently dropped. Fix the value the error names. (play_launch issue 0083; ros-launch-manifest v0.3.26.)
