The typed `nros_rmw::ClientTrait` helpers carry the request's sequence id, like the raw path. `send_request::<S>` returns it, `take_response::<S>` returns the reply with the id of the request it answers, and the new `take_response_for::<S>(id, buf)` delivers only that request's reply and drops a stale one (a resent request's predecessor answering late). This is a breaking signature change for out-of-tree callers of the two helpers. The workspace and Zephyr C++ service-client examples now use the `_seq` FFI pair and drop a reply that names another request. (issue 2033)
