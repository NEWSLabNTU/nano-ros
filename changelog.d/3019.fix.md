A configured CMake build now re-configures when a source tree it located moves, instead of building the tree it found first. Checking out a different commit in a pinned submodule, provisioning or removing a store copy with `nros setup --source`, or editing a project's `[sources]` used to leave an existing build directory compiling the old tree, with no message. `nros build` also notices a changed source override variable (`FREERTOS_DIR` and the like) or uncommitted edits in a pinned submodule; a plain `cmake --build` needs `cmake <build-dir>` re-run for those two.
