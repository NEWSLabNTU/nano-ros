`just check zephyr-workspace-foreign-checkout` refuses a Zephyr west workspace that names ANOTHER nano-ros checkout. A workspace inside one checkout whose `nano-ros` manifest project pointed at a different one made `west build` compile the application from one tree and the nano-ros Zephyr module — the zpico C shim, the platform and board headers, the RMW dispatch, the knob inventory — from another, silently, for a month; a mixed image builds, links and runs, and the two halves disagree only when one of them changes. The gate applies the same rule the build already uses for inherited paths (a path outside any checkout is fine, a path into a DIFFERENT checkout is not) to three places workspace state records it: the manifest project, every `CMakeCache.txt` in the workspace's build dirs, and the venv console scripts' shebangs — which carry the crossing into `WEST_PYTHON` and survive repairing the link. It is buildless and on the push lane, records a skip rather than an OK when no workspace is provisioned, and `just doctor` reports the same answer. `just zephyr setup` now also unbinds an already-provisioned workspace, so re-running it repairs the state instead of leaving it.
