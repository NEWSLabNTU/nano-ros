`ENTITIES` is out of the cmake grammar. It is no longer a `cmake_parse_arguments` keyword of `nano_ros_node_register` or `nros_components_register_node` — which makes the latter a keyword-for-keyword analog of upstream's `rclcpp_components_register_node` again — and the refusal a stale caller gets now reads `ARGN`, so it also catches the two spellings the parse-result test missed: `ENTITIES` swallowed into a preceding multi-value keyword, and `ENTITIES` dropped silently into `UNPARSED_ARGUMENTS`. Three `message()` remedies that had been telling readers to write the retired argument now name the two live surfaces instead (the bringup's `contract.yaml`, or a standalone leaf's `system.toml` `[[component]] entities`). `check-retired-cmake-keywords` now keeps that from recurring: a retired keyword may appear only inside its tombstone FUNCTION (it exempted all of `cmake/`, which is where the three remedies were), a tombstone's remedy may name only keywords its verb still accepts (which caught `nano_ros_entry`'s `HOST` refusal still telling readers to pass `MODEL`), and a retirement whose wording the gate cannot read fails instead of silently dropping out of the set
