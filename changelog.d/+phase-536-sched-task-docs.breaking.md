The scheduling unit's word moved from "tier" to "sched task" in nano-ros's records, messages and docs as well (phase 536 W4; RFC-0052 "Names"). Records other tools read: the priority plan and the priority record (`nros_priority_plan.json`) carry `sched_tasks` / `sched_task` (was `tiers` / `tier`), the sizing descriptor's per-sched-task rows are `[[sched_task]]` (was `[[tier]]`), and the board console markers say `sched_task=` (was `tier=`), e.g. `nros: core pin sched_task=`...; `nros-board-zephyr`'s cargo feature is `sched_tasks` (was `tiers`; `nros build` enables it itself). In `system.toml`, a `[[node_overrides]] callback_groups` row names its task as `task` (`tier` is still read). The other senses of "tier" (CI and test tiers, support tiers, CLI command tiers, the C API's polling/callback tiers, TIER IV) keep the word.
