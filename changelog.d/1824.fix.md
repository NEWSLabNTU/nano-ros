A C or C++ image built through CMake now takes its per-build config headers (`nros_config_generated.h`, `nros_cpp_config_generated.h`) from the `$OUT_DIR` of the cargo run that build made, placed by the same script the Zephyr lane uses, instead of from `$CARGO_TARGET_DIR/nros-{c,cpp}-generated/`, a directory cargo does not manage and that another build sharing the target dir could write. NuttX and PX4 still read the old location. ([#1824](https://github.com/NEWSLabNTU/nano-ros/issues/1824))
