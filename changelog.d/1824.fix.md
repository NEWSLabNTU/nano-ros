A C or C++ image built through CMake now takes its per-build config headers (`nros_config_generated.h`, `nros_cpp_config_generated.h`) from the `$OUT_DIR` of the cargo run that build made, placed by the same script the Zephyr lane uses, instead of from `$CARGO_TARGET_DIR/nros-{c,cpp}-generated/`, a directory cargo does not manage and that another build sharing the target dir could write. The NuttX app build (`integrations/nuttx/`) does the same: its cargo build runs under that placer, and `nros locate artifact c-include --placed-dir <dir>` answers the placed directory. A PX4 module (`integrations/px4/NanoRosPx4Module.cmake`) reads the headers from the directory its archive build placed them in, `build/nros-px4/placed` by default (`-DNROS_PX4_HEADER_DIR` / `NROS_PX4_HEADER_DIR` to override), so the documented archive command now runs `cargo build` under `scripts/build/cargo-out-dir-headers.py`; the module names the full command when the archive or headers are missing. ([#1824](https://github.com/NEWSLabNTU/nano-ros/issues/1824))
