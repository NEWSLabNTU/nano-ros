`rclcpp::Node::has_parameter` (and the lifecycle node's and `NodeParametersInterface`'s) now answers false for a launch parameter the node has not declared yet, as rclcpp does. The common `has_parameter(p) ? get_parameter(p) : declare_parameter(p)` idiom used to skip the declaration on nano-ros because the image seeds launch values before it builds the node; it now declares, and the declaration takes the launch value with the declared type.
