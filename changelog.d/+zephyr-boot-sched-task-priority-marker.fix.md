A Zephyr image now says which priority its boot sched task runs at. The boot thread adopts `sched_tasks[0]`'s declared priority with `k_thread_priority_set`, which Zephyr 3.7 does not trace, and nothing printed it, so a boot sched task that kept the main-thread default was silent. Both the C/C++ runner and the Rust entry read the priority back (`k_thread_priority_get`) and print `nros: sched task priority set sched_task=`<name>` prio=<n>`, the marker the FreeRTOS and NuttX seams already print, or `nros: sched task priority FAILED ...` naming both values when the kernel reports another.
