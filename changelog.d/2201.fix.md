An image that declares no entities no longer gets `NROS_MAX_LARGE_SUBSCRIBERS` derived from the number of large message TYPES it links. That count bounds nothing: it charged a publish-only image a large-payload block per linked large type, and it gave too few blocks to several subscriptions on one type. On that basis the count is now derived only when it is 0, and otherwise keeps its configured value. Declaring the image's `[[component]] entities` derives it from the actual subscriptions, which is 0 for a talker. An undeclared zenoh image whose closure has unbounded types is now told this at configure (issue 2201).
