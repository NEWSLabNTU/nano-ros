A C/C++ Zephyr image built by `nros build` now configures in one pass by construction, and a disagreement can no longer be papered over by an extra pass. The message-bound sizes the configure's early readers took from the resolve phase are checked at the end of the configure against what the configure composed. A different answer over the same inputs stops the configure and names both files. Inputs that moved since `nros build` resolved them converge as before, and the configure says to re-run `nros build`. The entity inventory the configure reads from the resolve is now keyed on the model's content as well as its path, so a configure re-run after a contract edit no longer takes the previous model's answer. Configures `nros build` did not start (a plain `west build` of a leaf) converge exactly as before. RFC-0094's A3 is amended to say this. ([#1252](https://github.com/NEWSLabNTU/nano-ros/issues/1252))
