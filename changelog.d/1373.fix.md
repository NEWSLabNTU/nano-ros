A freshly created worktree no longer dead-ends at the pre-push gates. `git worktree add` populates no submodules, and two of the 324 fast gates read one: `capability-conditionals` needs zenoh-pico's platform dispatch header, `xrce-vendored-versions` needs both vendored XRCE `CMakeLists.txt`. The new `just setup-worktree` checks out those three submodules and only those three - not the 20 that a bare `git submodule update --init` would fetch - and both gates now name it in their failure text. The XRCE gate used to advise `nros setup --source micro-cdr --source micro-xrce-dds-client`, which cannot run where that failure happens: a fresh worktree has no `target/`, so the `nros` on PATH belongs to another checkout and `setup` refuses a foreign binary.
