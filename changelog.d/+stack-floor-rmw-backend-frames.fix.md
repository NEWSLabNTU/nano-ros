The stack-floor check now sees an RMW backend's frames and the calls into it. Every backend's vtable calls are followed, as zenoh's already were. Before, a Cyclone, XRCE or uORB call through the vtable was charged 0 bytes, and a service path that put 64 KiB on the stack went unseen. The backend library is now built with `-fstack-usage` like the rest of the image. When the walk still cannot state a floor, the warning names the image, its RMW and the stack it ships with, says the stack is not checked, and says how deep the walk got. If that depth is already more than the stack, it says the image will overflow.
