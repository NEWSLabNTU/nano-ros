A CMake or plain `west` application no longer generates messages from the
copies nano-ros bundles when ROS 2 is not sourced. `find_package(<pkg>)` and
`nros_generate_interfaces` now stop when neither `NROS_INTERFACE_SEARCH_PATH`
nor `AMENT_PREFIX_PATH` names the package, with the remedy `nros configure`
gives: source ROS 2 and configure again. This keeps message layouts and type
hashes matched to the ROS 2 install your peers use, as `nros configure`
already did. To build from the bundled copies on purpose, add the directory
the error names (`packages/cli/interfaces` in the SDK root) to
`NROS_INTERFACE_SEARCH_PATH`. A sourced ROS 2 install is still read first
(issue 2278).
