A host that drives the executor itself can now ask how long it may sleep: `Executor::next_deadline_us()` (Rust), `rclc_executor_get_next_deadline_ns()` (C) and `rclcpp::Executor::next_deadline_us()` (C++) return the bound the executor's own park uses — the next wall timer, the backend's next internal event, a supervised route's deadline and every registered wake source — measured from now, with "no deadline" (`None` / `UINT64_MAX`) when nothing is scheduled. `spin_once`'s park now also counts the time the caller spent between two spins toward a timer's remainder, so it no longer oversleeps a timer by that gap (issue 2143).
