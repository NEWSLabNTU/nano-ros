An image whose largest receivable message is within 256 bytes of its zenoh reassembly ceiling (`NROS_ZENOH_FRAG_MAX_BYTES`, or the larger `NROS_ZENOH_BATCH_UNICAST_BYTES`) is now refused at configure, with an error that names the size to set. Before, such an image built, and every one of those messages was dropped at run time without an error: zenoh adds its own headers to each message, and those no longer fit.
