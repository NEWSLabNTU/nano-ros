The host-driven integration surface is retired (RFC-0113): nano-ros supports a way of running only where it decides which callback runs and at what priority, so a foreign async runtime or event loop is no longer supported. Deleted: `Executor::spin_async` and `spin_async_with_sleep`; `Executor::set_ready_notifier`, `ready_notifier_supported` and `ready_fd`, with C `rclc_executor_set_ready_notifier` and C++ `rclcpp::Executor::set_ready_notifier`; the public `Executor::next_deadline_us`, with C `rclc_executor_get_next_deadline_ns` and C++ `rclcpp::Executor::next_deadline_us`; `nros::setup!` and its `nros_setup` / `nros_deploy` / `nros_boot` / `nros_run_deferred` emit; `Executor::callback_mark` / `set_deferred_since` / `CallbackMark` and the `nros::node_runtime` host-drain functions; the tokio examples `service-client-async` / `action-client-async` and `listener-host-loop`. Drive the executor with `nros::main!` and tiers, or RTIC. The deferred-dispatch queue (`set_deferred`, `run_deferred`, `set_defer_notifier`) stays.
