# phase-328 — zpico multi-session (handle-passing)

**Resolves:** [issue 0348](../issues/0348-zpico-multi-session-support.md)
**Informed by:** issue 0347 (the single-session guard this relocates), RFC-0005
(RMW layer), RFC-0035 (vtable ABI — unaffected; this is below the RMW seam).
**Status:** Complete (2026-08-01) — all W1–W6 landed; capability verified green
(`two_sessions_deliver_cross_session_through_router`, `ZPICO_MAX_SESSIONS=2`),
single-session footprint delta +142 B `.bss` (W6).

## Decision

Issue 0348 Option **3** — full handle-passing. Every `zpico_*` entry point
takes a leading `zpico_session_t*`. The C shim's ~51 file-scope statics split:
per-session state moves into `zpico_session_t`; the diagnostic counters and the
ZID uniquifier stay process-global. Chosen over Option 2 (singleton-compatible
wrappers) for the clean end state — one spelling, no default-instance
ambiguity — accepting the atomic ABI break across the callers.

## Design

### Allocation — compile-time pool, no heap

```c
#ifndef ZPICO_MAX_SESSIONS
#define ZPICO_MAX_SESSIONS 1        // single-session targets keep TODAY's footprint
#endif
static zpico_session_t g_sessions[ZPICO_MAX_SESSIONS];
static bool            g_session_inuse[ZPICO_MAX_SESSIONS];
```

`zpico_session_t*` is an opaque handle into the pool. No `malloc` (embedded
rule — heap is not assumed). At the default `ZPICO_MAX_SESSIONS == 1` the pool
holds exactly one struct's worth of the same tables that are file-scope today,
so a target that only ever opens one session pays **the current static budget
plus one `bool`** — the 0348 footprint acceptance is satisfied structurally,
not by measurement luck. `ZPICO_MAX_SESSIONS` is raised (Kconfig / `-D`) only by
a multi-domain build.

### `zpico_session_t` members (per-session)

session handle `g_session`, `g_config`, `g_session_open`, `g_initialized`;
registration tables `publishers/subscribers/liveliness/queryables`; queryable
reply state `stored_queries/stored_query_valid/last_reply_seq`; `pending_gets`;
`reply_waker`; the tx-batch flush cadence (`last_batch_flush`/`batch_flush_init`,
today function-local statics in `zpico_spin_once`); and the cfg-gated
per-platform spin/flush/read primitives (`spin_sem` | `spin_sem_posix`+init |
`spin_mutex`+`spin_cv`+init | `threadx_read_mutex`+init; `tx_flush_task`+run;
the read/lease task copies applied at open).

### Stays process-global

The 18 `g_diag_*` counters (preserves the `zpico_get_diag_counters(out[18])`
ABI) and `g_session_zid_counter` (a cross-session ZID uniquifier — global *by
design*; the atomic form exists so parallel opens draw distinct ZIDs).

### Callback context — pack, don't back-point

The zenoh-pico closures (`sample_handler`, `query_handler`,
`pending_get_reply_handler`/`_dropper`) and the flush thread recover per-session
state today via an `int idx` closure arg or pointer arithmetic against the
global array base (`(pending_get_slot_t*)ctx - g_pending_gets`). Both break once
the arrays live inside a pooled struct. Fix: pack `{session_idx:u16,
slot_idx:u16}` into the existing `void* ctx` (no per-entry back-pointer, so the
footprint delta stays ~0), and pass `zpico_session_t*` as the flush task `arg`
(currently `NULL` at the `_z_task_init` site). `_zpico_notify_spin` and
`_zpico_threadx_locked_read` take `zpico_session_t*`.

### Config-setter carve-out (documented exception to the handle rule)

`zpico_set_task_config` and `zpico_set_flush_task_config` are called **before a
session exists** (board boot path — `nros-board-freertos`, `mps2-an385`
`startup.c`). They stay process-wide *defaults* copied into the session at
`zpico_open`. Boards are untouched. `zpico_set_reply_waker` is NOT exempt — it
is per-session (Rust holds `*const Context` at the call site).

### Rust surface

`nros-rmw-zenoh/src/zpico.rs`: `Context` (a ZST today) gains
`handle: *mut zpico_session_t`; `Context::new`/`with_config` acquire+init+open a
pool slot; `Drop` closes+frees. Thread the handle into `Publisher`/`Subscriber`/
`Queryable`/`LivelinessToken` (the latter two hold only `i32` today — add the
handle field). `ZenohSession { context }` already owns the per-session object,
so the RMW layer above is unchanged.

## Lockstep API surfaces — change together or the header drifts

1. `packages/rmw/zenoh/zpico-sys/c/zpico/zpico.c` — the impl.
2. `packages/rmw/zenoh/zpico-sys/c/include/zpico.h` — regenerated by cbindgen.
3. `packages/rmw/zenoh/zpico-sys/src/lib.rs` — `extern "C"` import block.
4. `packages/rmw/zenoh/zpico-sys/src/ffi.rs` — `cbindgen_stubs` (drive header sigs).
5. `packages/rmw/zenoh/zpico-sys/cbindgen.toml` — `[export].include` allowlist.
6. `packages/rmw/zenoh/nros-rmw-zenoh/src/zpico.rs` — safe wrapper.

C consumers that create the singleton and must capture the handle:
`zpico-zephyr/src/zpico_zephyr.c` (+ `.h`), `nros-bench/stress-zenoh-zephyr/src/main.c`.

## Work

- **W1 — C struct + pool + config carve-out.** Define `zpico_session_t`, the
  `g_sessions[ZPICO_MAX_SESSIONS]` pool + `alloc`/`free`, move per-session
  globals into the struct, leave diag + zid global, keep the two task-config
  setters process-default and copy them into the session at open. Every
  `zpico_*` body: `g_x` → `s->x`. Every `!g_session_open` guard → `!s->…`.
- **W2 — callback plumbing.** Pack `{session_idx, slot_idx}` into closure ctx;
  flush-task `arg` = `s`; `_zpico_notify_spin(s)` / `_zpico_threadx_locked_read(s)`;
  `reply_waker` per-session. This is the load-bearing half.
- **W3 — Rust FFI + wrapper.** lib.rs extern block, ffi.rs cbindgen stubs,
  cbindgen.toml allowlist, then `zpico.rs` `Context` handle + thread through the
  wrapper types and the 8 direct `zpico_sys::…` calls. Regenerate `zpico.h`.
- **W4 — C consumers.** `zpico-zephyr.c`/`.h` return + carry the handle;
  `stress-zenoh-zephyr/main.c` captures + passes it.
- **W5 — test flip.** Replace 0347's
  `second_session_open_in_one_process_is_refused` with
  `two_sessions_deliver_cross_session_through_router`: two `ZenohTransport::open`
  in one process on the SAME topic+domain (session A subscriber, session B — the
  second open — publisher), assert A receives B's message. Same domain is what
  makes them match; independence is proved by A surviving B's open. Skips when
  built with `ZPICO_MAX_SESSIONS=1` (second open returns `Err`); the multi-session
  lane rebuilds with `ZPICO_MAX_SESSIONS=2`.
- **W6 — footprint gate.** — **MEASURED** (host x86-64, `ZPICO_MAX_SESSIONS=1`,
  `zpico.o` before/after via `git stash`): `.bss` 21505 → 21647 (**+142 B,
  +0.66 %**), `.data` 0 → 0, `.text` +1673 (flash). The per-session tables
  (`g_sessions[1]` = 21440 B) did NOT multiply — the +142 B is
  `g_session_inuse[1]` plus struct-aggregation alignment padding, immaterial
  against the ~21 KB table budget. `.text` growth is the handle-deref +
  acquire/release/pack-unpack helpers (flash, not the tight `.bss` budget the
  issue guards). A 32-bit embedded target's delta is no larger (smaller
  pointers).

## Acceptance (from issue 0348)

- Two `ZenohTransport::open()` in one process → two independent sessions;
  registrations on the first survive the second opening (same-domain
  cross-session delivery test, `ZPICO_MAX_SESSIONS=2`).
- The 0347 refusal test is replaced by that delivery test.
- Single-session embedded footprint does not materially grow (measured, W6).
