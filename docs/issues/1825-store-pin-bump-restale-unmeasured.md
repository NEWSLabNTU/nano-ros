## What is left

[phase-440](../roadmap/archived/phase-440-nros-store-is-the-root.md) was
archived on 2026-10-12. Its W7 (the per-project pin and dispatch by it) landed
with one acceptance clause named as still open.

**The claim:** "a pin bump re-stales generated code through #182". On the
contributor path, #182 keys regeneration on the CLI source stamp. On the user
path it would key on the toolchain version. That is the same machinery pointed
at a different input, but nothing tests it on the user side. phase-440 also says
that two projects building side by side need a real release asset.

**What already exists:** the user-path probe phase-440 W8 asked for has landed
as `just probe installed` (phase-447 A3). It builds the asset that
`release-nros.yml` would publish and runs `first-project.md` on a host with no
checkout. It does not bump a pin.

## What closes it

Extend the installed-path probe, or add a test beside it: build a `nros new`
project against pin A, bump the project's pin to B, rebuild, and assert that the
generated code was regenerated by B's codegen (by its codegen version, RFC-0090).
Two projects pinned to different versions on one host would cover the
side-by-side case too.
