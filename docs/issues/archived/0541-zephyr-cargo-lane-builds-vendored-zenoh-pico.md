## Symptom

`just build-test-fixtures lane=all` fails the whole zephyr lane (rc=2), every
Rust leaf:

```
zenoh-pico/include/zenoh-pico/system/platform/zephyr.h:18:10:
  fatal error: version.h: No such file or directory
   18 | #include <version.h>
```

Reproduces on a single leaf, and reproduces identically with
`NROS_ZEPHYR_PRISTINE=always` — so it is not a stale or partial build dir.

## Cause

`292547dd5 fix(#529, #530)` added a `zephyr` arm to `platform_name`:

```rust
} else if use_zephyr {
    Some("zephyr")
```

with the reasoning:

> No behaviour change today: `build_c_shim` is skipped on Zephyr (below), so the
> config header these knobs feed has no consumer …

`build_c_shim` is indeed skipped on Zephyr. But `platform_name` gates TWO call
sites, and the other one is not the shim:

```rust
if let Some(name) = platform_name {
    …
    build_zenoh_pico_unified(…)   // the whole vendored zenoh-pico C build
}
```

Before #529, Zephyr fell through every arm (`is_embedded_target()` excludes it
from the posix arm) and resolved to `None`, so the cargo lane compiled NO
zenoh-pico C. After it, `Some("zephyr")` switches that build ON.

On Zephyr the C sources belong to the CMAKE module (`zpico-zephyr`), which
supplies Zephyr's include dirs through `zephyr_include_directories`. `version.h`
is GENERATED by the Zephyr build (`include/generated/zephyr/version.h`), and the
cargo lane has no path to it and never did. Issue 0460 is the same seam from the
other side: the Zephyr RUST lane inherits nothing from cmake, so anything it is
asked to compile against Zephyr headers fails.

The comment was right about the knob-config consumer and missed that the same
variable is the on/off switch for a much larger build.

## Fix

`if let Some(name) = platform_name.filter(|_| !use_zephyr)`.

`platform_name` stays TOTAL over the platforms with a config file, which is what
#529 wanted for the knob ladder; the vendored-C build stays off the Zephyr cargo
lane, which is what it was before. The comment's own claim is now true of both
call sites rather than one.

## Verified

```
NROS_ZEPHYR_FIXTURE_FILTER='build-rs-talker-zenoh' just zephyr build-fixtures
  -> exit 0, 0 fatal errors
```

The only remaining mentions of `version.h` in the log are Zephyr GENERATING it
(`[918/1244] Generating include/generated/zephyr/version.h`) — the header the
cargo lane was wrongly trying to consume.

## Note for the next total-ification

Making a discriminator total is usually right, and was right here. The hazard is
that `platform_name` is overloaded: it names a knob-table row AND decides
whether to build vendored C. A reader checking one consumer will conclude the
change is inert. Splitting those two meanings would make the next such change
safe by construction; not done here, because this fix is small and the
regression is live on main.
