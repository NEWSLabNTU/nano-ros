## Symptom

`just ci gate`, step `check::build`, gate `dist-runtime-deps`, on a host whose
SDK store holds `arm-fvp` (`~/.nros/sdk/arm-fvp`):

```
check-dist-runtime-deps: a dist needs libraries its `system = [..]` does not name:

  [tool.arm-fvp]  libatomic.so.1  — no [prereq.*] declares this soname
```

The result does not depend on the branch: it reads the installed store and
`nros-sdk-index.toml`, and was measured on two trees (a phase-483 W2 worktree
and the W3 branch) with the same output.

## Cause

`[tool.arm-fvp]` in `nros-sdk-index.toml` has no `system = [..]` list, and no
`[prereq.*]` entry provides `libatomic.so.1`. The gate measures the
`DT_NEEDED` closure of the dist's programs (issue 1452), and
`bin/FVP_BaseR_AEMv8R`'s closure needs it.

A host without `arm-fvp` installed never sees this, which is why it reads as
green elsewhere.

## Fix

Add a `[prereq.libatomic1]` entry (`provides = ["libatomic.so.1"]`, apt
`libatomic1`), and name it in `[tool.arm-fvp] system = [..]`. Then check whether
the runner image generated by `scripts/ci/runner-container.sh` needs the
package too, since it is derived from the same index.

## Resolution (2026-10-10)

Fixed on `main` by `5210fd0538` ("fix(index): declare libatomic.so.1 for the
arm-fvp dist"), filed from another session the same day without an issue.
That commit adds `system = ["libatomic1"]` to `[tool.arm-fvp]` and a
`[prereq.libatomic1]`, and records the DT_NEEDED sites with readelf
(`libarmctmodel.so`, `libscxframework.so`, `newt.so`, the trace plugins).
This issue is kept as the record of the measurement that found it.
