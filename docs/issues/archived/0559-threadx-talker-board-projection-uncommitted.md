## Symptom

After any `just build-test-fixtures lane=native`:

```
$ git pull --rebase
error: cannot pull with rebase: You have unstaged changes.

$ git status --short
 M examples/threadx-linux/rust/talker/.cargo/config.toml
?? examples/threadx-linux/rust/talker/.cargo/nros-board.toml

$ git diff
-include = ["../../../../../nros-patch.toml"]
+include = ["../../../../../nros-patch.toml", "nros-board.toml"]
```

Hit twice in one session. Each time the only way forward is
`git checkout -- <that file>`, which throws away output that will be
regenerated by the next build.

## Cause

`nros sync` projects a board's `cargo_config` into
`<leaf>/.cargo/nros-board.toml` and adds it to the leaf config's `include`.
The generated file states its own contract:

> This file IS committed (unlike sync's `nros-managed-patch.toml`): its content
> is a fixed string in a committed descriptor, identical in every checkout, and
> a fresh clone must be able to LINK this leaf before any sync has run.

**39 leaves commit both the projection and the include. `threadx-linux/rust/talker`
commits neither**, so sync legitimately writes both on every build and the tree
is dirty every time.

That also means a fresh clone of this leaf lacks a projection its board
declares — the LINK-time gap issue 0440 exists to prevent — until someone runs
sync.

## Fix

Commit the projection and the include, matching the 39. Sync's write is then a
no-op instead of drift.

Verified: `nros sync` in the leaf now leaves the tree clean, `cargo metadata`
resolves (exit 0), and `check-cargo-config-tracked` passes ("tracked <=>
hand-authored content").

## What this issue does NOT claim

I first read this as "three tracked configs include an untracked
`nros-board.toml`", which would have been issue 0463's hard parse error. That
was wrong — an artifact of grepping the string anywhere in the file rather than
in the `include` line. Checked properly: **39 configs name it in `include`, and
all 39 have it committed. Zero mismatches.** The three "broken" leaves resolve
fine (`cargo metadata` exit 0). Recorded because the wrong version was
alarming and the right one is narrow.

## The sibling asymmetry, left alone deliberately

talker's five siblings (`listener`, `action-client`, `action-server`,
`service-client`, `service-server`) share `deploy = "threadx-linux"` and have NO
projection — not committed, and none generated even by an explicit `nros sync`.
So this is not "five more leaves are missing theirs"; something about talker
specifically makes sync project for it. Whether that difference is intended is a
phase-341 question, and normalising all six on a guess would be the larger
error. Flagged rather than swept.

## Reproduce

```sh
source ./activate.sh
just build-test-fixtures lane=native
git status --short examples/threadx-linux/rust/talker
```

Before: a modified tracked config plus an untracked projection. After: clean.
