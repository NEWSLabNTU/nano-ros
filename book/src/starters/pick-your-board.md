# Get started on your board

<!-- type: how-to · level: 1 -->

**Needs first:** [Install](../start/install.md)

Pick the board you have, or the one you want to try, and follow its starter.
Each starter takes you from a finished install to a talker on that board whose
messages you read with `ros2 topic echo`. It needs nothing from the Tutorial,
and it takes about half an hour, most of it the first build.

Every starter has the same steps:

1. **What you need:** the board or emulator, a cable if there is a board, and
   the host packages.
2. **Provision:** `nros setup <board>` fetches the board's cross-compiler,
   emulator and sources into `~/.nros`.
3. **Scaffold the project:** `nros new <workspace> --board <board> --template
   talker` writes a workspace with one talker node.
4. **Run it:** `nros run <node>` builds the image and runs it in the
   emulator, in the board's twin, or on this machine.
5. **Flash the board,** for a board you can hold: `nros flash --monitor`.
6. **See it in ROS 2,** with `ros2 topic echo`.

## How the list is ordered

The list below is generated from the board support registry, and each entry
shows the board's status as the registry states it.

- **Twin and hardware** come first. Each of these boards has an emulator
  twin that boots the very image you later flash to the board, so you can
  run the starter today and buy the board when you are ready.
- **Emulated boards** run in QEMU on your machine. Nothing needs to be
  bought, and an automated lane runs each of them.
- **Host boards** run as ordinary programs on your Linux machine, with no
  emulator at all. They are the fastest way to try nano-ros.

A board that is not listed has no starter yet. Its page under
[Supported Boards](../reference/supported-boards.md) says what nano-ros can
show for it.
