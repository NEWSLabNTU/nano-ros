An image names a board that no board descriptor claims, so nano-ros does not
know what to build it for.

`[image.<id>] board` in a bringup's `system.toml` is where an image names its
board. Each board crate ships a descriptor whose `names` list says which
spellings it answers to, and several are aliases for one board
(`mps2-an385-baremetal`, `baremetal` and `bare-metal` all name one
descriptor). A name that none of them lists is refused by name rather than
guessed at, because a guess builds the wrong image and reports success.

## How to fix it

Check the spelling in `system.toml`:

```toml
[image.demo]
board = "mps2-an385-freertos"
```

`nros board list` prints every board this SDK has. If the board is your own,
its board package must be on the board search path.

## Design background

- The catalog's one resolution rule (names, then the directory alias, then
  the platform) is issue 0606.
