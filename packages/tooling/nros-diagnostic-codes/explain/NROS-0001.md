`nros configure`, `nros build` or `nros run` stopped before building anything,
because this shell has not sourced ROS 2 and the project has messages to
generate.

nano-ros generates every message type a project uses (a talker's `std_msgs`,
for example) from the message definitions of your ROS 2 install, so the types
and their hashes match your ROS 2 peers. It finds that install through
`AMENT_PREFIX_PATH`, which sourcing ROS 2 sets. A configure that ran in a
sourced shell records the prefix in the project, so later commands do not
need it; this project has no such record yet.

It happens on every board and every RMW, Linux and Cyclone DDS included.

## How to fix it

Source ROS 2 once, in this shell, and run the same command again:

```bash
source /opt/ros/humble/setup.bash   # or your overlay's install/setup.bash
nros build
```

That configure records the prefix in the project. Later builds and runs of
the same project reuse it, from any shell, an IDE or a CI step. A new project
records its own, so its first build needs a sourced shell again.

## Design background

- RFC-0120 D2: with no recorded prefix, configure refuses rather than
  guessing one.
