# What every sizing knob COSTS, when a `// nros-pool:` formula cannot say — issue 0815.
#
# `scripts/gen-pool-inventory.py` finds every knob mechanically, and prices a pool
# only where the pool declares its arithmetic as a product of knobs. Most of the
# RAM those knobs move is not such a product — its element is a struct whose size
# only the compiler knows, or it lands on a heap, or inside the executor's
# storage — and the page used to render those knobs with NO cost column at all,
# which a reader takes as "free". This file is the WHY for each of them.
#
# It is an AUTHORED table, so it is bound in both directions by the generator,
# which FAILS (it is the `pool-inventory` gate) when:
#   * a scanned knob has neither a pricing formula nor a row here (UNCLASSIFIED);
#   * a row names a knob the scan no longer finds (stale);
#   * a `pool`/`heap` row names a symbol no tracked source defines any more.
# A row may also annotate a knob a formula already prices, to name the OTHER
# pools it sizes.
#
# Format:  KNOB | kind | symbols (comma-separated, may be empty) | reason
#
# kinds
#   pool        sizes the named static(s); priced EXACTLY per image by
#               `just mem-report`, which measures the symbol and lists the knobs
#   executor    sizes the executor's storage — `mem-report`'s
#               `[executor storage]` owner
#   component   sizes the per-component storage — `[component storage]`
#   heap        sizes a heap region or what is allocated from one; a named
#               symbol is the region itself, measured by `mem-report`
#   stack       sizes a stack — a task's, or one call's frame
#   element     sizes a field or element; the bytes land in whatever pool, arena
#               or handle holds that type
#   input       an input to ANOTHER knob's derivation, never storage itself
#   not-a-size  a time, priority, threshold or switch — costs no bytes
#   test-only   read only by a test binary
